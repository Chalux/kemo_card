# kemo_card：卡牌共斗 Roguelike 设计规格

**日期**：2026-05-11  
**状态**：已合并对话设计稿第 1～4 节，并经自检修订  
**范围**：玩法规则、系统边界、宿主/Mod 分界、持久化与测试要点（不含具体实现代码）

---

## 1. 目标与约束

### 1.1 产品形态

- **本地单人**；规则上玩家操控 **4 名角色** 对抗 **AI 敌人**。
- **每名角色**拥有 **独立牌库、手牌、弃牌堆**（资源不共用）。
- **Roguelike 进程**：节点推进 + 节点结束后的 **分支选项**；Run 开始前必须选择 **故事脚本**（每 Run 唯一）。

### 1.2 工程约束（与仓库规则对齐）

- **游戏本体**：仓库内 **纯 C#**（Godot Mono）。
- **Mod 脚本**：可使用 **Lua / TypeScript / Python** 等，由 **C# 脚本宿主**统一加载与沙箱化 API。
- **组合优先于继承**：管理器与系统服务以组合方式拼装（不在本文展开类图）。

---

## 2. 总体架构与宿主/Mod 分界

### 2.1 七大管理器（权威注册中心）

下列管理器各自囊括该类对象定义，**由配置决定**，并支持 **动态注册**；凡 **未注册** 的引用一律 **非法**：

1. 角色  
2. 战斗  
3. 事件  
4. 卡牌  
5. 道具（主要为药水等消耗品）  
6. 技能  
7. Buff  

**刷新时机**：仅在 **游戏启动** 或 **Mod 启用/禁用** 时更新管理器内容；运行期对定义池 **只读**（避免运行中热更定义导致不可诊断不一致）。

### 2.2 非法语义（与对话一致）

- **非法技能**：执行时 **无操作**（可记录诊断日志）。  
- **非法 Buff**：**不挂载**到角色；Buff **仅允许由技能**尝试添加。  
- **卡牌/角色**可映射到 **一个或多个技能**。

### 2.3 C# 核心职责

- **运行态服务**：Run 状态机、战斗阶段机、卡牌执行队列、即时技能通道、目标合法性校验与回滚规则、Run 账本等。
- **脚本宿主（Script Host）**：
  - 向 Mod 脚本暴露 **受控 API**（白名单命令 + 只读查询）。
  - 禁止脚本直接操控引擎对象图；脚本输出必须是 **可校验的结构化 DTO**。
  - **随机性**：与 Run 相关的随机（含选项生成、同优先队列平局）必须使用 **宿主派生的 RNG 流**；脚本禁止自带会破坏可复现性的随机源。

### 2.4 关键原则

- **单一事实源**：注册表在 C#；脚本只 **提议**，宿主 **校验 + 原子提交**。
- **不可逆门闩**：与账本相关的写入必须发生在宿主判定的 **不可逆提交点**（见 4.2 / 5.3）。

## 3. 战斗与回合状态机

### 3.1 顶层节拍（单轮）

1. **玩家阶段**
   - 可随时切换 **当前操控角色**。
   - 对当前角色：
     - **卡牌使用**：选卡 → 选目标 → 将条目推入 **卡牌执行队列**。
     - **即时技能**：可施放 **任意友方角色** 的技能；**即时结算**，**不进入卡牌队列**。
   - 玩家对某角色点击 **确认** 后，将该角色标记为 **已行动**。
   - **仅施放即时技能**（且未触发 3.4 的回滚规则时）**不改变** 已行动/未行动状态。
   - 当 **四名角色均为已行动**：进入 **卡牌执行阶段**。

2. **卡牌执行阶段**
   - 使用 **优先队列/小根堆**：主排序键为 **卡牌内置优先级数值（升序，数值小优先）**。
   - **同优先级平局**：使用 **Run 种子驱动的随机次序**（可复现）。
   - 队列清空后进入 **敌方阶段**。

3. **敌方阶段**
   - 执行敌人行动（由战斗注册内容定义；AI 细节可在实现阶段补充）。
   - 结束后回到 **玩家阶段**（四人回到 **未行动**；能量/抽牌等经济规则若后续引入，不得与本节状态机冲突）。

### 3.2 卡牌队列项（最小字段建议）

- 持有者角色 id  
- 卡牌 id + 运行时实例 id  
- 优先级  
- 目标集合（可判断“是否包含某敌人”）  
- 入队序号/时间戳（用于 UI 与诊断；不作为主排序键）

### 3.3 玩家阶段：目标失效与「未行动」回滚

以下情况将相关队列项的 **持有者** 置为 **未行动**（并应触发 UI 提示）：

- 玩家 **取消** 已确认要使用的牌，且原因包含目标不再合法。
- **即时技能结算后**对比快照：相对技能执行前仍存活的敌人集合，若出现 **丢失敌人**（死亡/离场等），则队列中凡以这些敌人为目标或目标集合 **包含** 这些敌人的卡牌：其 **所属角色 → 未行动**。

### 3.4 执行阶段：目标在轮到前被前置效果破坏

当轮到某张牌时，若其目标已不合法：

- **单体目标**：先在 **仍合法的单体目标集合** 中 **自动重选**；若找不到新目标 → **跳过该牌（空放）**，且 **不把持有者打回未行动**。
- **多目标（多选）**：**不尝试改选** → **跳过该牌（空放）**，且 **不把持有者打回未行动**。

**重选默认策略**：优先由 **卡牌注册逻辑** 提供 `RetargetPolicy`；若未提供，则由宿主定义统一默认（例如：在合法单体池中按宿主 RNG 选择），并在实现计划中固定，避免实现期争议。

## 4. Roguelike：节点、选项、账本与故事脚本

### 4.1 节点产出

- 故事脚本生成：**节点类型（nodeType）** + **节点 id（nodeId）**（及可选载荷）。
- 宿主必须校验注册表合法性；非法则拒绝并按 **兜底策略** 处理（重掷/安全节点/中止等需实现期固定优先级，且必须具备 **重掷上限** 以防死循环）。

### 4.2 节点结束后的选项菜单

- 节点结束（战斗结束 / 离开商店 / 事件结束等）后，宿主调用故事脚本：输入 **层数 + 种子 + Run 状态（含账本摘要）**，输出 **选项列表（结构化 DTO）**。
- 玩家选择后，仅当宿主判定为 **不可逆提交** 时，才允许写入与推进（避免半提交）。

### 4.3 Run 账本（去重与可重复）

- 记录 **`ExperiencedBattles`** 与 **`ExperiencedEvents`**：表示 **已不可逆执行过** 的战斗/事件（建议使用稳定注册 id）。
- **写入时机（已确认）**：当玩家在 **节点已结束之后的下一步分支** 做出 **不可逆选择** 时入账本（“仅刷新未执行”的仍可再次出现）。
- **卡牌与道具（药水）**：允许重复刷新（统计可与账本分离）。

### 4.4 默认执行与故事覆盖

- 节点进入后默认执行 **注册内容** 逻辑。
- 故事脚本可通过宿主允许的机制 **覆盖/包裹** 部分执行逻辑，但 **不得绕过非法校验**。

## 5. 错误处理、日志、持久化与测试

### 5.1 错误分级

- **致命（Fatal）**：状态机/存档一致性被破坏。策略：中止当前操作并强日志（含 seed、storyId、层数、定义版本摘要）。
- **可恢复（Recoverable）**：非法 id、脚本 DTO 校验失败、节点生成失败。策略：拒绝提交 + 兜底路径 + 可见提示（开发模式更详细）。
- **软失败（Soft）**：非法技能无操作、非法 Buff 不挂载、执行阶段跳过空放牌。策略：继续流程 + 可开关诊断日志。

### 5.2 日志与轨迹（里程碑建议）

- 记录：不可逆选择、阶段切换、队列执行（含重定向/跳过原因）。
- 脚本异常：捕获并记录脚本栈与宿主上下文；默认不让脚本崩溃拖死主线程（失败则走可恢复路径）。

### 5.3 持久化：两类存储（Run + 全局）

#### 5.3.1 Run 存档（单次闯关）

建议最小字段集合包含：

- `seed`、`storyId`、层数/进度  
- `ExperiencedBattles` / `ExperiencedEvents` 账本  
- 队伍与卡组运行时、RNG 流状态（含同优先随机子流）  
- 当前节点与未提交选项（若存在）  
- **定义版本**：各管理器内容版本/哈希；加载时若与当前环境不一致，必须提示 **回放/继续风险**。

#### 5.3.2 全局存档（跨 Run）

与 Run 存档分离，持久化 **全局进度与偏好**，包括但不限于：

- **成就**进度与解锁状态  
- **已解锁内容**（角色、故事脚本、卡牌皮肤、难度等，以实际产品为准）  
- **设置**（音量、语言、显示、输入、可访问性等）

**一致性建议**：

- 全局存档与 Run 存档使用 **不同文件/不同存储键**，避免一次损坏全丢。  
- 全局存档写入建议 **原子写**（临时文件 + 替换）并保留 **备份槽**（实现期细节）。  
- 对 Mod 变更敏感的全局字段（解锁依赖内容版本）应记录 **内容版本**，避免静默错位。

### 5.4 测试策略

- **单元测试（C#）**：优先队列排序性质、账本写入门闩、玩家阶段回滚、执行阶段单体重选/多选跳过。  
- **确定性测试**：固定种子下关键路径可复现。  
- **集成冒烟**：启动加载管理器 → 开 run → 节点闭环 → 不可逆写入 → 存档读档一致性（Run 与全局分别覆盖）。
