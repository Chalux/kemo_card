# kemo_card：四人小队卡牌 Roguelike（本地单人）设计规格

**日期**：2026-05-11  
**状态**：已评审合并（第 1～4 节 + 全局持久化补充）  
**范围**：玩法与系统边界、宿主/Mod 分界、错误处理与持久化；不含具体数值与美术规范。

---

## 1. 总体架构与宿主/Mod 分界

### 1.1 分层

- **C# 核心（随游戏发布）**
  - **七大管理器**：角色、战斗、事件、卡牌、道具、技能、Buff；在 **游戏启动** 与 **Mod 启用/禁用** 时构建/刷新注册表；运行期对定义池 **只读**（与「管理器内内容只在该时机更新」一致）。
  - **运行态服务**：Run 状态机、战斗阶段机（玩家阶段 / 卡牌执行 / 敌方）、卡牌 **优先队列**（主键：卡牌内置优先级升序；平局：**Run 种子驱动的随机次序**）、即时技能通道、目标合法性校验与 **未行动回滚**、Run **账本**（不可逆选择触发写入：战斗/事件去重；卡牌/药水可重复）。
  - **脚本宿主（Script Host）**：为 Mod 暴露 **受控 API**（白名单命令 + 只读查询）；加载/卸载脚本；向脚本输入 **节点类型、节点 id、层数、种子、Run 快照**；接收脚本产出的 **可校验结构化结果**（选项列表、节点覆盖意图等）。**禁止脚本直接操控 Godot 节点图或绕过校验写入游戏状态**。

- **Mod 脚本（Lua / TypeScript / Python 等）**
  - 主要负责：节点结束后的 **选项生成**、**节点类型 + 节点 id** 的生成、以及对默认注册逻辑的 **覆盖声明**（仍必须经宿主校验并转为命令）。
  - **非法引用**在宿主侧统一失败：未知 id → 不执行 / 不挂载 / 不生成可用选项（细则见第 2、3 节）。

### 1.2 关键原则

- **单一事实源**：注册表在 C#；脚本只 **提议**，宿主 **校验 + 原子提交**。
- **可复现**：与随机相关的内容（优先队列平局、选项生成、默认单体重选等）必须使用 **由 Run 种子派生的宿主 RNG**；脚本不得使用脱离宿主的自造随机源破坏复现性。
- **账本写入时机**：「战斗/事件已经历、全局不再重复」在玩家对 **节点结束后的选项** 做出 **不可逆选择** 时写入（见第 3.3、3.4 节）。

### 1.3 语言边界（用户确认）

- **项目内**：纯 **C#** 实现游戏本体与宿主。
- **Mod**：脚本可使用 **Lua / TypeScript / Python** 等，由宿主统一加载与沙箱策略约束。

## 2. 战斗与回合状态机（含队列、技能、回滚）

### 2.1 参与者与资源

- **小队**：本地单人操控 **4 名角色**；每名角色 **独立牌库、手牌、弃牌**。
- **敌人**：由 **战斗节点**（`战斗` 管理器注册内容 + 可选故事覆盖）实例化；**敌方阶段**按该战斗定义行动。
- **技能**：卡牌或角色可映射 **一个或多个** 技能 id。**非法技能**：结算时 **不执行任何操作**（可记诊断日志）。
- **Buff**：**仅技能**可尝试添加到角色。**非法 Buff**：**不添加**。

### 2.2 顶层节拍（单轮）

1. **玩家阶段**
   - 可随时切换 **当前操控角色**。
   - 对当前角色：可将 **卡牌** 以「选卡 → 选目标 → 入队」加入 **卡牌执行队列**；也可施放 **任意友方角色的即时技能**（**即时结算**，**不与卡牌队列混排**）。
   - **仅**当玩家对该角色点击 **确认** 后，将该角色标为 **已行动**。
   - **仅施放即时技能**（且未触发下文「目标丢失回滚」）**不会**改变任何人的 **已行动/未行动**。
   - 当 **四名角色均为已行动**：进入 **卡牌执行阶段**。

2. **卡牌执行阶段**
   - 使用 **优先队列**（或小根堆）：按 **优先级数值升序** 弹出；同优先级按 **Run RNG** 打破平局。
   - 队列清空后：进入 **敌方阶段**。

3. **敌方阶段**
   - 执行敌人行动（具体 AI 可在实现计划中展开）。
   - 结束后：回到 **玩家阶段**（四人 **未行动**；每轮资源重置策略由经济系统另行规格化，本文不展开）。

### 2.3 队列项（最小字段建议）

- 持有者角色 id、卡牌 id、运行时实例 id、优先级、目标集合（可判断「是否包含某敌人」）、入队序号（用于 UI/诊断，非主排序键）。

### 2.4 目标失效与「未行动」回滚（玩家阶段内）

以下情况将 **受影响队列项的所属角色** 置为 **未行动**（并需 UI 反馈）：

- 玩家 **取消** 已确认要使用的牌，且原因包含目标死亡或不再可用等。
- **即时技能结算后**对比快照：相对技能执行前仍存活的敌人，若出现 **丢失敌人**（死亡/离场等），则队列中凡以这些敌人为目标或目标集合 **包含** 这些敌人的卡牌：**其所属角色 → 未行动**。

### 2.5 卡牌执行阶段内：目标在轮到前被前置效果破坏

- **单体目标**：轮到该牌时，尝试在 **当前仍合法的单体目标集** 中 **自动重选**；若 **找不到**新目标 → **跳过该牌**（空放），**不把持有者打回未行动**。
- **多目标（多选）**：不尝试改选 → **跳过该牌**，**不回滚未行动**。
- **重选策略**：优先由 **卡牌注册逻辑** 提供；未提供时由宿主 **统一默认**（例如合法池内按 Run RNG 选取），并在实现计划中写死默认策略以便测试。

## 3. Roguelike Run（节点、账本、故事脚本协作）

### 3.1 Run 启动

- Run 开始前 **必须** 选择 **故事脚本**（唯一）。
- Run 固化：**种子**、**故事脚本 id**、层数/进度上下文、管理器版本摘要（用于诊断）。

### 3.2 节点模型

- 故事脚本产出：**`nodeType` + `nodeId`**（及可选载荷）。
- 宿主校验：必须在对应管理器注册；非法则拒绝并按 **第 4 节** 可恢复错误处理。

### 3.3 节点结束后的选项

- 节点结束（战斗结束、离开商店、事件结束等）后，宿主调用故事脚本：输入 **层数、种子、Run 状态（含账本摘要）**，输出 **结构化选项列表**。
- **不可逆选择**提交时：执行账本写入与状态推进（见下节）。

### 3.4 Run 账本（去重与可重复）

- 记录 **已不可逆执行** 的 **战斗** 与 **事件** id：**之后不再出现**。
- **曾刷新为可选项但未执行**：**不入账本**，可再次出现。
- **卡牌与道具（多为药水）**：允许重复刷新（可与统计字段共存，但不使用「已经历」账本禁止刷新）。

### 3.5 默认执行与故事覆盖

- 节点进入后默认执行 **注册内容**；故事脚本可通过宿主允许的 **覆盖声明** 包裹/替换部分逻辑，但 **不得绕过非法校验**。

## 4. 错误处理、日志、持久化与测试

### 4.1 错误分级

- **致命**：状态机/存档校验等不可恢复错误 → 中止并强日志。
- **可恢复**：非法 id、脚本 schema 失败、节点生成失败 → 拒绝提交 + 兜底（重掷上限、安全节点）。
- **软失败**：非法技能无操作、非法 Buff 不挂载、执行阶段跳过牌 → 继续 + 诊断日志。

### 4.2 日志与轨迹

- 建议记录：不可逆选择、阶段切换、队列执行（含重定向/跳过原因）；脚本异常带语言栈与宿主上下文。

### 4.3 持久化（两类存储）

**A. Run 存档（单次闯关）**

- 建议包含：`seed`、`storyId`、层数/进度、`ExperiencedBattles` / `ExperiencedEvents`、队伍与卡组运行时、**RNG 流状态**（含优先队列平局子流）、当前节点与未提交选项（若有）、各管理器内容版本/哈希（加载时提示不一致风险）。

**B. 全局存档（跨 Run，用户补充）**

- 与单次 Run **分离存储**，例如：
  - **成就**（解锁条件、进度计数、领取状态）
  - **已解锁内容**（角色、卡牌池、故事脚本、难度、装饰等）
  - **玩家设置**（音量、语言、显示、输入、可访问性等）
  - 其他元进度（统计、图鉴、新手引导标记等）
- **版本与迁移**：全局存档需 **schema 版本号**；升级时做 **向前迁移** 或 **字段默认值回填**；与 Mod 列表变更的兼容性在实现计划中定义（例如：成就 id 与 Mod 内容哈希关联策略）。

### 4.4 测试策略

- 单元测试：优先队列、账本门闩、玩家阶段回滚、执行阶段单体重选/多选跳过。
- 确定性：固定种子下脚本 DTO 与关键随机路径可复现。
- 集成：管理器加载 → 开 run → 节点闭环 → 存档/读档 → 全局设置读写冒烟。
