## 1. 参与者与胜负

### 1.1 小队与敌人

- 玩家操控三名角色。队伍共用战斗抽牌堆与墓地，每张牌保留构筑角色的归属，出牌由该角色支付能量。
- 敌人由战斗定义（波次 / 生成）实例化；敌方阶段按 AI / 定义行动；敌方单位使用 **独立 HP**（非共享）。

#### 1.1.1 多生命条与固定行动循环（2026-10-10）

- `EnemyDto.lifeBars` 声明每条生命的 `maxHp` 与 `actionSequence`；每项含 `skillId`、`actionCount`（默认 1）。无生命条配置时沿用单条 HP 与原 AI。生命条均应用生成配置 `hpScale`。
- `actionCount` 为本项需要等待的敌方回合数：1 立即行动；2 等待一回合再行动。只有完成行动才推进循环；外部行动延迟不会消耗循环步骤。
- 任一伤害包仅扣当前生命条，不传递溢出伤害。存在下一条时，卡牌执行阶段（包括后续普攻）至该敌人开始行动前破条，暂留当前条 0 血，保持合法目标与存活判定，获得不可驱散的【免疫所有伤害】。敌方阶段轮到该敌人时移除免疫、清空状态、补满下一条，从新循环第一项开始；先清掉旧条的行动延迟，再检查新条行动计数。其余区间破条立即换条。
- 换条不结束当前回合，不重放敌人首次入场行动或波次开始钩子。仅最后一条归零才阵亡并参与清波判定；换波仍结束当前回合。
- 状态重置移除该敌人所有 Buff、GE、护盾与行动延迟，包括不可驱散状态。内容可用 `persistAcrossLifeBars: true` 明确保留 Buff / GE。重置不分发移除钩子，避免移除过程重新建立旧状态；其他角色与队伍领域不随该敌人换条重置。
- `entrySkillRefs` 在首次入场初始化时执行一次，不占行动循环；换条不重复执行。换条以 `EnemyLifeBarChangedEvent` 值事件驱动血条与条数显示，破条伤害事件保持 `TargetAlive = true`，不会提前播放阵亡退场。
- 「初启的兄弟」两波依次为凯尔（红 / 人类，400→400，物攻 5）与佐治（绿 / 人类，400→600，魔攻 5），其余攻防为 0。定值攻击不额外叠加源攻击力，仍结算防御；佐治第二条全体攻击为 `15 + 100% 魔攻`。减攻使用 `Independent` 新实例、各减 6 并持续 3 回合；咏唱永久不可驱散、每层魔攻 +10、上限 15。凯尔入场在每名角色随机一槽施加本场战斗持续的出牌伤害 5。

**2026-10-11 黑熊战斗与循环扩展**：

- `EnemySpawnDto.initialActionIndex` 为首条循环的 0 起索引，必须在循环范围内；换条仍从新循环首项开始。生命条可独立声明 `entrySkillRefs`，首次生成执行首条入场动作，后续换条在清空状态、补满生命并发换条事件后执行新条入场动作一次，不消耗常规行动。
- 生命条可同时声明 `prioritySkillId` 与 `requiredAliveEnemyTag`：存在该标签的存活敌人时每次以计数1执行优先动作，不推进常规循环；条件消失后从常规循环首项开始。死亡同伴不满足条件。
- 敌方技能 `enemyRandomTargetRepeats` 默认1，允许1～100次，仅多次时要求 `Enemy / RandomN / targetCount:1`。第一轮沿用已解析目标，后续每轮重新随机（继续遵守嘲讽），允许重复命中；每轮完整执行载荷，因此伤害和破甲逐次配对结算。文案统一写「随机1名角色N次」，不使用「随机N名角色」表示可重复命中。
- `ApplyBuff` 可用 `stacks` 指定投放次数，或用 `stackMultiplier` 按现有层数补足倍数（0层保持0层，遵守 Buff 上限）；`requiredEnemyTag` 限定敌人定义标签。`GainResource / currentEnergy` 的负 amount 降低每回合额度 `CurrentEnergy` 和当前可用余额，最低0，不改 `MaxEnergy`；之后照常每回合再生。波次入场扣额度发生在新回合再生之前。
- 「森林黑熊来袭」三波为普通黑熊×2（600；第二只从循环第2项开始）、普通／精英／普通（600／800→1000／600；普通均从第1项开始）、首领（1200→1500）。全为黄元素动物，基础攻防均0。普通入场各给每名角色随机一槽永久暴风强度1（同槽替换）。咆哮每层物攻+5，永久可驱散、上限20；仅首领咆哮跨条保留并在第二条入场翻倍。首领第一条入场队伍能量额度-2，破甲每击新增物防-6的3回合独立实例。精英第二条有普通黑熊时只给普通黑熊2层咆哮，失去全部普通黑熊后进入单独循环；公式伤害分别按125%和150%实时物攻计算，定值攻击不叠加物攻。

**2026-10-11 不死恶灵、召唤与战斗机制**：

- `BattleWaveDto.entryMechanisms` 独立声明波次入场扣血（`id`、`maxHpDamagePercent`，`turn:0`）。首次满血初始化后／换波敌人初始化后各执行一次，不随单个敌人入场或召唤重放。数额按触发时队伍未取整 `MaxHealth` 计算，通过唯一队伍生命写入口直接扣血；不走攻防、倍率、护盾、普通伤害规则、免疫／致命伤钩子、受击成长或魔法受击记账，也不属于任何敌人的行动。死亡立即进入 Defeat，不再执行回合开始治疗。表现使用独立 `BattleMechanismDamageEvent`。
- 生命条 `turnStartMechanisms` 使用相同结构，`turn` 必须为正整数。正式切换该条时记为第1回合，每个全局回合开始在治疗、时长和抽牌管线前检查；按敌人实例／生命条／机制ID去重。旧条0血等待期间不启动新条倒计时，敌人最终死亡后不再触发其机制。
- `prioritySkillId` 除同伴标签条件外，可改配 `prioritySummonCondition: { enemyId, maxAlive, maxSummons }`，两类条件互斥。存活数量不足且本条行动召唤额度未用完时，每次计数1执行召唤，普通循环暂停并保留进度；补齐或额度耗尽后续接原步骤。召唤额度按来源敌人／生命条／召唤定义记录，换条重置，场上存活幽灵不会被重置或清除。
- `SummonEnemy` 动作参数为 `enemyId`、`count`、`maxAlive`、`maxSummons`、`trackLifeBarSummons`。实际数量同时受人口空位、单次数量和剩余额度约束；入场补足可设置 tracking=false。新敌人从同一工厂创建、赋独立运行时ID、接入GE与入场钩子，并追加到敌方列表，既有索引不变。敌方阶段以阶段开始快照行动，新召唤者在下一个敌方阶段才可行动；波次结束／胜利也包含这些单位。`EnemySummonedEvent` 驱动界面追加节点。
- **固定手牌槽封印已停用**：`AttachSlotBuff` / `DiscardSlot` 空过；幽灵的封印技能仍占行动循环但不再产生效果（见 §2.5 角色级封印）。界面不再显示槽位封印。
- Buff `deferFirstTurnEnd:true` 在新建／刷新后跳过一次回合结束递减，使敌方行动中的减攻、封印持续完整后续玩家回合；只允许 Turns 且 Independent／Refresh／Replace，避免共享层时长。其余 Buff 保持原时长规则。
- 「发现不死恶灵」仅两波：幽灵×2（800；魔攻20；第二只错位起手）、幽灵／恶念／幽灵（恶念1800→2400→2800、魔攻40；幽灵同起手）。皆蓝元素、不死｜未知，其他攻防0。两波各触发上限25%／80%机制扣血；幽灵逐次随机角色并尝试施加2回合封印，但固定手牌槽效果停用后该技能空过（只消耗行动）。恶念常规三步为随机1名角色2次各50魔伤、全体后续1回合双攻-10、全体50魔伤，定值攻击不额外叠加源魔攻。三个生命条分别补至2／3／4只幽灵，行动召唤总额4／5／8只、单次1／2／2只，不含第二／三条入场补足。第三条第10回合开始造成上限9999%机制扣血。

### 1.2 共享 HP（唯一玩家生命账本）

- 胜负只看 **队伍共享 HP**；**v1 无单角色倒地**。三槽在 `SharedHp > 0` 期间全程可行动、可被点名（减员压力用 **封印**，见 2.5，不用死亡态）。
- 玩家角色 **无 Health 当前值**，仅有 **MaxHealth**（贡献 `MaxSharedHp`）。凡「残血 / 生命%」类条件与效果一律读 **SharedHp / MaxSharedHp**；内容读写玩家槽位 `Health` 当前值 → 校验失败或软失败。
- `MaxSharedHp = sum(各上阵角色当前 MaxHealth)`，可在战斗中随 MaxHealth 变化 **重算**。
- **SharedHp 仅存在于本场战斗内**；Run / 非战斗层不持久化「当前共享血量」。
- 开战：在 BattleStart 被动/修饰结算之后，按当时公式得到 `MaxSharedHp`，`SharedHp = MaxSharedHp`（恒补满一次）。
- **BattleStart 通道约束**：被动自动技能与修饰技能 **禁止读写 SharedHp**（伤害、治疗、直接改血）；只允许改属性 / `MaxHealth` 等，再由补满步骤冻结账本。若将来要「带伤开战」，须另改管线，不得依赖现有顺序碰运气。
- 重算 `MaxSharedHp` 时：**不** 按比例缩放 `SharedHp`；该重算路径不读改 SharedHp。若出现 `SharedHp > MaxSharedHp`，立刻 `SharedHp = min(SharedHp, MaxSharedHp)`。
- 伤害扣共享 HP；治疗加共享 HP，不超过 `MaxSharedHp`。
- `SharedHp <= 0` → 败北；敌方全灭（或战斗定义的胜利条件）→ 胜利。
- 同场 **多波**：跨波 **保留** `SharedHp` / 按规则重算的 `MaxSharedHp`，不因清波回满。

### 1.3 玩家侧点选与结算（L1 + T1 + D2 + B2）

- **点选**：卡牌/AI 仍可点 **槽位角色**（`Self` / `Ally` 等语义保留），用于点名、Buff、按槽修正。
- **分槽伤害（D2）**：对每个目标槽用该槽（及来源）ASC 分别结算；每次结果 **分别** 扣 `SharedHp`。AoE **禁止**「算一次再 ×N」。
- **内容约定**：对玩家的多目标/全体伤害，数值按 **单槽期望伤** 来写，并注明会按命中槽数多次扣 Shared。
- **Team / Shared 直伤**：与 Heal 对称；内容使用显式 **Team / Shared** 目标规格时，对账本 **只结算一次**（不走分槽点名）。禁止把「全体一次」与「分槽 AoE」混用语义。
- **内容声明方式（2026-07-28 决议）**：`ETargetScope` 新增 **`Team`** 档——`side` 继续表达敌我相对关系，`scope: Team` = 对该侧队伍账本一次结算；`scope: All` = 分槽逐次结算（D2）。玩家侧 `Heal` 必须 `scope: Team`；`Heal` + 玩家侧 `Single/All` → 内容校验失败。
- **护盾 / 格挡 / 槽位减伤**：挂在被点名的槽位上；仅当该次伤害目标含该槽时参与该次结算（B2）。Team/Shared 直伤 **不** 吃分槽护盾（除非效果显式另写）。
- **伤害包管线（2026-09-19 统一）**：**所有**伤害写入——GAS 公式通道（GE 的 `Damage` 执行）、直伤定值通道、充能球通道——一律 先 `OnBeforeDamage`（可改数额、可完全抵消）→ 写入 → 再广播 `OnAfterDamage`（只读观测最终数额）。分槽护盾规则按 `packet.Target.Index` 匹配槽位，因此账本目标（`Index < 0`）天然不吃分槽护盾，与上一条一致；队伍级减伤规则则可以点名账本目标参与结算。
- **三条通道的差异只在"数额怎么算"**：GAS = `Amount + 源攻×attackScale + 源 Damage 属性 − 目标对应防御`（源攻/对应防御由 `damageType` 决定，见下一条；`attackScale` 缺省 1.0）；直伤 = 定值；充能球 = 定值 + `attackBonusScale × 产球者攻击`；普通攻击 = `攻击力 × 系数 − 目标对应防御`。缩放口径见下条。
- **增伤与受伤增加一律加算，只有连携是乘算（2026-09-21 决议，全游戏统一）**：
  ```
  最终伤害 = base × (1 + Σ增伤 + Σ受到伤害增加) × (1 + 连携加成)
  ```
  - **进同一个加算桶**（不分攻防两侧、不互相乘算）：`DamageDealtScale`（全伤害增加）、`CardDamageDealtScale`（卡牌增伤）、`NormalAttackDamageDealtScale`（普攻增伤）、`DamageTakenScale`（受伤倍率）、`NormalAttackDamageTakenScale`（普攻受伤增加）、`OrbDamageScale`（球伤害增加，可带元素掩码）。
  - **唯一的乘算因子是连携**：它是"多人同属性协奏"的档位奖励，语义上不属于单次伤害的增伤。
  - 理由：多条增伤若互相乘算，同时吃到受伤倍率时会指数放大，数值不可预期；加算后每条增伤的实际收益是固定的线性叠加，便于平衡与向玩家解释。
  - 治疗不受影响（`治疗 = (amount + 源 HealPower) × (1 + 连携)`）。
  - 实现入口：`DamageExecution`（GAS 通道）与 `DamageScaling`（mod 侧：直伤 / 普攻 / 充能球共用）。
- **伤害维度自 2026-09-20 起拆成两维**：`DamagePacket.Kind`（`Elemental` / `Physical` / `Magical`）+ `DamagePacket.Element`（`EElement`，可多元素或空）。物理/魔法吃目标对应防御（物防/魔防），`Elemental` 不吃防御；元素标签供未来克制/抗性使用。充能球与普通攻击都按该结构标注。**2026-09-21 起 GAS 通道也落到这两维**（原 §7 后置项已清，见本文 §7 与 §14.5）：`ExecutionDefDto.damageType`（`Physical` 默认 / `Magical` / `Elemental`，也兼容旧的"直接写属性名"写法）+ 可选 `element`（`Red`/`Blue`/`Green`/`Yellow`，多属性逗号分隔）由 `DamageTypeParser` 解析 → `DamageExecution` 据此选攻/防 → `GameplayEffectApplicator` 把维度随 `SharedHpSettlement` 传进伤害包管线。写错的 `damageType`/`element` 会被内容准入拒绝，不会静默退化成"物理无属性"。
- **治疗**：只回队伍 Shared；内容须使用显式 **Team / Shared** 目标规格。`Heal` + 点名队友（如 `Ally+Single`）→ **内容校验失败**。不存在「对某个队友回血」。

## 2. 顶层阶段机

### 2.1 节拍

1. **BattleStart**
   - 按总规格 2.2 / 4.7：**先**按槽位 `0 → 2`、角色定义顺序挂载每名上阵角色的**全部被动**，**再**按插入序释放共享 **修饰技能**；各尝试一次（均不得读写 SharedHp，见 1.2）。
   - 然后按公式冻结 / 得到当时 `MaxSharedHp`，`SharedHp = MaxSharedHp`。
   - 从队伍牌堆 **开局抽至全队共 10 张手牌**（见第 4、6 节）。
   - 进入首个 **玩家阶段**（走第 6 节管线；能量「当前能量」首回合不 +1；技能计数器首回合仍 +1；**首回合不再**按公式抽牌）。
2. **玩家阶段（即时出牌）**
   - 可切换当前操控角色；界面显示全队手牌与牌堆张数。
   - **出牌**：点击或拖拽合法卡牌 → 扣所属角色当前可用能量 → **立即离手并完整结算**（无标记入队、无 `priority` 排序、无逐角色确认）。效果结算完毕后进入队伍墓地；腾出的手牌位可供本回合后续抽牌使用。
   - **主动技能**：`CastActiveSkillCommand`（见第 5 节）；即时结算；**不占**行动。
   - **消耗品**：全队共享 5 槽，可在玩家阶段使用（见 §4.7 与 Run 规格）。
   - **结束回合**：全队共用一个「结束回合」；本回合允许打零张或多张牌。提交后进入 **弹珠阶段**。
3. **弹珠阶段**
   - 锁定本轮轮值角色并开始弹珠操作（瞄准 / 发射 / 标记 / 倍速 / 暂停 / 提前结束，主动技与消耗品入口见 §12）。
   - 待发队列与活跃球均为空，或玩家满足条件提前结束时，锁定最终 `Count` 并进入结算阶段。
   - 飞行途中若因技能 / 消耗品 / 撞钉效果导致敌方全灭，立刻中断并按清波 / 判胜逻辑结算。
4. **结算阶段（`CardExecution`）**
   - 执行轮值普攻与追打（见 §12）；零 `Count` 完全空过，不写伤害、不发命中事件。
   - 先判全灭 / 换波 / 胜负，再进入敌方阶段。
5. **敌方阶段**
   - 执行敌人行动；回合结束钩子；检查胜负；未结束则 **回合数 +1**，再进入下一玩家阶段（完整回合开始管线）。
   - **"回合开始"每回合只发生一次**（2026-09-20 修正）：只有"回合数 +1 之后"（以及开战时的首个回合）会触发 `FireTurnStart`；进入敌方阶段不补发。
   - 敌人无 `skillRefs` 时没有行动意图、不执行行动；**行动计数门闩** `ActionCount`（默认 1）> 1 时本回合只减 1 不行动，设为 2 即把本次行动推迟到下一回合（`SetActionCount`，缺省 2、下限 1）。
6. **换波与 Boss 血条**
   - **玩家阶段出牌清波**：当前效果完整结算后再换波；有下一波则玩家继续当前回合，保留手牌与剩余能量；换波不额外补牌、不恢复资源、不触发轮值普攻。
   - **点击结束回合后清波**（弹珠普攻 / 敌方阶段 / 回合结束效果）：下一波进入下一个正常玩家回合，照常补牌与恢复资源；新敌人在该玩家回合结束后才行动。
   - **Boss 破条**：卡牌打空非末条血时保持换条保护，轮到自己行动时才切换；同回合后续段数与出牌无法打到下一条血（§1.1.1）。
   - **全灭即结算**：任何时点打死最后一名敌人都立即判定；回合结束管线每回合只结算一次（幂等守卫）。

### 2.2 队列项（已废止：即时出牌）

> 2026-11-23 起出牌即时结算，不再有「手牌标记 → 执行队列」模型；本节原队列字段、`paid` 与执行排序仅用于理解历史存档 / 旧讨论。现行规则见 §2.1 与 §4。

### 2.3 玩家阶段：自动取消与未确认回滚（已废止）

> 即时出牌在提交时完成目标校验与扣费，效果立即结算，不存在「已标记牌的目标失效回滚 / 未确认态」。旧规则见归档的《单机三人队与即时出牌重构决策》与本文变更记录。

### 2.4 执行阶段：目标失效（已废止）

> 即时出牌在点选 / 拖拽提交瞬间解析目标；非法目标直接拒绝，不进入等待执行状态。旧队列期的单体改选与多目标子集规则不再适用。

### 2.5 封印（角色级）

减员 / 硬控用封印，不用单角色倒地。

- **效果**：持有 `combat.state.sealed` 的角色 **禁止出牌**、**禁止释放主动技**（软失败）；其他角色与其自身资源管线不受影响。
- **资源**：玩家阶段开始管线（能量 / `S` / 抽牌）**照常**；封印不跳过角色、不清手牌、不退还费用。
- **弹珠轮值**：被封印角色仍正常担任本回合轮值普攻角色（封印只限制出牌与主动技）。
- **中途挂上封印**：立刻阻止后续出牌 / 主动；已经提交并结算的效果不回滚。
- **免疫封印**：持有 `trait.immune_seal` 的角色不吃封印，见 §14.8.3。
- **固定手牌槽效果移除**：旧「槽位封印 / 槽位充能 / 计时 / 相邻槽」随固定手牌槽一并停用；封印是角色级状态。

## 3. 能量

### 3.1 定义字段与运行时

| 名称 | 来源 | 含义 |
|------|------|------|
| 初始能量 `initialEnergy` | 角色定义 | 开战时 **当前能量** 的初值 |
| 最大能量 `maxEnergy` | 角色定义 | **当前能量** 可成长到的上限 |
| 当前能量 | 运行时 | 每回合开始用来灌入「当前可用能量」的额度 |
| 当前可用能量 | 运行时 | 出牌扣费池；**可以超过** `maxEnergy` |

### 3.2 规则

- 开战：`当前能量 = clamp(initialEnergy, 0, maxEnergy)`，再按第 6 节灌可用能量。
- 每个玩家阶段开始（**非首回合**）：`当前能量 = min(当前能量 + 1, maxEnergy)`。
- 然后：**当前可用能量 = 当前能量**（覆盖，不累加残留）。
- 技能 / 效果增加的是 **当前可用能量**，可超过 `maxEnergy`；默认 **不** 提高「当前能量」成长曲线（除非另有专门效果）。

### 3.3 出牌扣费（即时出牌）

- v1 实装费用类型：**Energy**、**None**。其它 `ECostType`（Health / Gold / Discard / X）可展示，战斗提交 **拒绝**（软失败）。
- **Health 费语义预定**（本轮不实装）：将来若开放，= 扣 **SharedHp**（非槽位血），并另写预扣 / 执行扣与拒绝是否退血。
- **Energy**：提交出牌时按当前费用结算；可用能量足够才受理，受理成功后立即扣除。目标非法、角色封印、手牌已离开等校验失败时 **不扣费**。
- **None**：不扣。
- **没有取消 / 退费**：即时出牌一旦受理并完成结算，卡牌进入队伍墓地；不存在标记取消、`paid` 对账或费用上涨自动取消。
- **手牌槽费用归零已移除**：固定手牌槽效果停用，`slot.free_cost` 不再生效。

## 4. 抽牌、手牌与弃牌

### 4.1 手牌模型（即时出牌）

- 全队共用 **最多 10 张手牌**。各角色持牌数由实际抽到的牌决定，一名角色可以持有全部 10 张。
- **出牌即离手**：合法出牌在扣费后立即离开手牌并完整结算，随后进入队伍墓地；腾出的空位可供本回合后续抽牌使用。
- **没有标记队列 / 逐角色确认**：点击与拖拽共用即时结算规则。
- 未打出的手牌 **跨回合保留**。
- 抽牌时若全队已满手：**超出部分不处理**（不抽 / 不溢出进弃牌），牌堆顺序保持原样。

### 4.2 每回合抽牌数（公式）

- 基准 **1**。
- 增益效果只取 **最大 +N**；减益只取 **最大 −N**（不叠多段）。
- 每名角色贡献的抽牌数为 `max(0, 1 + 最大增益 − 最大减益 + 额外抽牌张数之和)`。普通抽牌修正仍取同向最大值；明确写为可叠加的额外抽牌独立累加，下次抽牌步骤后一起清除。
- **开局满手** 不走本公式；**首个玩家阶段** 不再公式抽牌。自 **第二** 个玩家阶段起，每阶段开始合计各角色的抽牌数，依次从队伍牌堆顶抽取，全队满手即停止。

### 4.3 战斗中途抽牌

- 允许在回合内通过卡牌、技能与被动触发即时抽牌；抽牌始终受 **全队 10 张手牌上限** 与队伍牌堆循环约束。
- 有明确角色筛选的抽牌及定向补满只取目标角色归属的牌；无显式角色目标的队伍抽牌从共享牌堆抽取。
- **弹珠阶段过滤**：`Draw` / `DrawByDiscard` / `FillHand` / `ModifyDrawCount` / `ModifyDrawCountByDiscard` 等只服务于出牌阶段的效果在弹珠阶段空过；`DrawByDiscard` 仍按最近一次实际弃牌数计算，`FillHand` 仅在主动技通道补到全队满手。
- 洗回规则见 §4.4；抽牌表现事件按实际入手顺序记录。
- 原「禁止中途即时抽牌」规则已废止。

### 4.4 牌堆循环

- 出牌完整结算后进入队伍墓地。结算中的牌暂时离开两个牌堆。
- 普通抽牌从队伍牌堆顶依次抽取。全队手牌有空位、抽牌堆为空且墓地能供牌时，洗回整个墓地后继续抽取。单回合洗回次数不限。

### 4.5 开战牌库

- 战前按角色构筑，开战把全队当前构筑合并洗牌。每张牌记录拥有者与独立的运行时实例 ID。开局最多抽 10 张，由全队共用。

### 4.6 中途弃牌（Discard）

各角色弃置的牌均进入队伍墓地，与出牌结算共用一堆。弃牌通道如下。

1. **默认规则**：没有明确写“随机”的弃牌按玩家选牌处理。`Discard` / `DiscardAndRecord` 的 `params.random` 缺省为 false；随机弃牌必须显式写 `random: true`。
2. **主动技能选牌**：释放确认后进入选牌态，点选手牌再确认；`CastActiveSkillCommand.DiscardCards`（运行时实例 ID）或 `DiscardSlots`（槽位快照）携带选择，在扣技能进度前检查数量、唯一性、范围与非空。固定弃 N 张按 `min(N, 现有手牌数)` 选择；`allowFewer: true` 则允许 0～N 张。ESC 或切换操控角色取消，不消耗资源。
3. **即时出牌与弃牌**：出牌已即时离手，弃牌只从手牌池取牌；不使用标记态 / `paid`。主动选牌按效果与目标分组的配额执行，非法选择在扣技能进度前拒绝；选牌不消费随机流。
4. **自动通道**（卡牌效果、敌方、Buff、回合结束）：显式随机只从当前可弃手牌中弃置，并避开同次技能已选定、待后续弃置的牌；没有选择上下文的非随机弃牌不擅自改为随机，零操作并累计 `BlockedUnselectedDiscardCount`。固定手牌槽的 `DiscardSlot` 已随固定槽效果停用。

现有出货中需要选牌的技能：南门二「半人马α」至多 2 张、爱因斯坦「万间雅祝」至多 2 张及充能 I 的至多 3 张（沿用已存在文案）。`discard_demo` 是未接入出货角色的显式随机示例。

## 5. 主动技能与蓄力链

### 5.1 内容声明

角色定义显式字段（与扁平 `skillRefs` 分离）：

```text
activeSkillChain: [
  { skillId, cooldown },  // [0] 基础主动
  { skillId, cooldown },  // [1] 蓄力Ⅰ
  ...                     // 蓄力 N
]
```

- 至少 1 项；每项 `cooldown >= 1`。
- `Cap = sum(各档 cooldown)`。
- 战斗主动按钮 **只读** `activeSkillChain`。

### 5.2 技能计数器 `S`

- 开战：`S = 0`。
- 每个玩家阶段开始（**含首回合**）：`S = min(S + 1, Cap)`；已达 `Cap` 则不再增长。
- 可放条件：`S >= C0`（基础档冷却）。

### 5.3 释放解析（自动最高档）

一次释放 **永远** 打出当前达标的 **最高档**，玩家不可故意降档。

累计阈值（解锁区间）：

- `S >= C0` 且 `S < C0+C1` → 基础（k=0）  
- `S >= C0+C1` 且 `S < C0+C1+C2` → 蓄力Ⅰ（k=1）  
- …  
- `S >= Cap` → 最高蓄力  

示例：`C0=4, C1=6, C2=6`，`Cap=16`：

| S | 放出 |
|---|------|
| 3 | 不可放 |
| 4–9 | 基础 |
| 10–15 | 蓄力Ⅰ |
| 16 | 蓄力Ⅱ |

**扣费（溢出资保留）**：放出第 **k** 档时，扣除解锁该档的累计阈值 `T_k = C0 + C1 + … + Ck`，然后：

1. `S = max(0, S − T_k)`  
2. 再执行该技能的 `actionRefs` / `effectRefs`（此处可显式 `S+N` 做成连发）

例：`S=15` 放蓄力Ⅰ → 扣 `T_1=10` → `S=5`（溢出资保留，同阶段仍可能再放基础）。  
例：`S=10` 放蓄力Ⅰ且效果含 `S+4` → 先扣 10 → `S=0` → 效果后 `S=4` → 可再放基础。

同一玩家阶段内：扣减并跑完效果后若仍达标，允许再次释放。连发应优先靠技能效果显式加 `S`，而非只扣单档 `Ci` 留下残层。

### 5.4 指令、阶段与封印

- 指令：`CastActiveSkillCommand(characterIndex, targets)`——**不带 skillId**，由宿主按 `S` 解析。
- **目标校验（2026-07-28 决议）**：`targets` 按指令受理瞬间解析出的 **将释放档位** 的目标规格校验；链上各档 **允许** 配置不同目标规格；UI 须跟随当前 `S` 展示对应档位的选目标模式。校验失败 → 拒绝指令（可见提示），不消耗 `S`。
- 即时结算，**不扣**卡牌可用能量，**不占**行动（即时出牌没有逐角色行动态）。
- **阶段权限**：可在 **玩家阶段** 与 **弹珠阶段** 释放。弹珠阶段仅允许未标记 `cardPhaseOnly` 的技能；技能自身不满足阶段 / 状态条件时拒绝请求且不消耗资源。
- **封印**中对该角色主动软失败（§2.5）。
- 卡牌 / 消耗品触发的 `skillRefs` / `useSkillRefs` **不走**本计数器。

### 5.5 技能载荷

- 技能被调用后，其 `actionRefs`（优先）或 `effectRefs` **同步即时执行完毕**。
- 非法技能 id：无操作（软失败）。

## 6. BattleStart 与玩家阶段开始管线（权威顺序）

### 6.1 BattleStart

1. 全部被动（槽位 `0 → 2`、角色定义顺序；禁读写 SharedHp）  
2. 修饰技能（按插入序；禁读写 SharedHp）  
3. 按公式冻结/得到当时 `MaxSharedHp`，`SharedHp = MaxSharedHp`  
4. 开局从队伍牌堆抽至全队共 10 张手牌（可洗牌；不走每回合公式）

> 2026-09-19 / 2026-09-20 补充：开战 buff 的注入顺序与容器见 §13.1.3（玩家侧全部被动在技能注入之后、冻结 SharedHp 之前；敌方 `EnemyDto.buffRefs` 在冻结 SharedHp 之后、`onWaveStart` 之前）。

### 6.2 每个玩家阶段开始（含首个）

对 **每名** 玩家角色依次：

1. （**非首回合**）`当前能量 = min(当前能量 + 1, maxEnergy)`  
2. `当前可用能量 = 当前能量`（覆盖）  
3. `S = min(S + 1, Cap)`（**含首回合**）  
4. （**非首回合**）按 4.2 计算实际抽牌数并抽牌（含每阶段至多一次洗牌）  
5. 若该角色处于 **封印**：资源管线照常；后续出牌与主动技被拒绝（2.5）  
6. **不做**「阶段开始统一处理已标记费用」——即时出牌没有标记费用

## 11. 充能球（元素球）系统（原 充能球规格 §1–§8）

> **原规格**：`2026-09-19-charge-orb-system-design.md`（**日期** 2026-09-19；**状态** 已实装）→ 归档于 `Doc/archive/superpowers/specs/2026-09-19-charge-orb-system-design.md`。
> **原关系**：服从 [2026-05-11 总规格](2026-05-11-kemo-card-design.md) 与本文；与 [buff 运行时 / 槽位效果 / 连携（见本文 §13）] 同批落地（槽位充能、连携、潜能）。
> **段号对应**：§11.1–§11.8 依次等于原规格 §1–§8，原段号注记在各节标题上。

### 11.1 球类型与内容注册（原 §1）

- 新内容类别 `orbs`（`content/orbs/*.json`，DTO `OrbTypeDto`）：Mod 与 base-game 走同一条内容管道（校验失败即剔除、归属 mod、翻译扫描自动覆盖）。
- 内建 6 种（base-game 声明）：红 / 蓝 / 绿 / 黄（元素球）+ 物理球 + 魔法球。
- 字段：
  - `dealsDamage`：是否造成伤害；`false` = 纯效果球（只跑 `triggerEffects`）。
  - `damageKind` + `element`（2026-09-20 拆维）：元素球 = `Elemental` + 元素（必填）；物理球 = `Physical`；魔法球 = `Magical`（物理/魔法球不带元素）。
  - `perOrbAmount`（内建 6）：每球固定伤害基数。
  - `attackBonusScale`（内建 1 = 100%）：产球者攻击的加成比例。
  - `attackSource`：`Higher`（物攻/魔攻取较高者，元素球）/ `Physical`（物理球）/ `Magic`（魔法球）。
  - `triggerEffects`：每球额外执行一次的效果引用（特殊球用）。
- **特殊球**（Mod 注册）不能由回合结束统计产出，只能经角色 / 卡牌 / 效果（`GainOrb`）授予。
- 校验：悬空 `triggerEffects` 引用、负的伤害基数 / 加成比例、纯效果球却没有触发效果、元素球却没有元素，一律拒绝；`GainOrb` 的 `orbTypeId` 必须存在。

### 11.2 队列与触发（原 §2）

- **全队共享**队列（FIFO，容量 7 = `OrbQueue.Capacity`），每个球记录**球类型 + 产球者**（产球时的玩家槽位；`<0` = 无产球者）。
- **主动触发**：出牌阶段球数 ≥ 3（`OrbQueue.ManualTriggerThreshold`）时可触发，**可重复**（只要仍 ≥ 3）；走正式玩家命令 `TriggerOrbsCommand`（不占行动、不消耗能量，因此不推动阶段推进）。
- **被动触发**：球数达到容量上限时**获得即触发**，立即结算后继续原流程（回合结束产出导致满员 → 就在回合结束时结算）。
- **触发结算**：一次清空队列全部球，按入队顺序（FIFO）**逐球**结算 —— 每个球执行一次自身类型的效果，源为**该球的产球者**。
- 敌方无存活目标时**照常清空、不产生伤害**（避免满员后卡死队列）。

### 11.3 单球伤害公式（原 §3）

```
单球伤害 = (perOrbAmount + attackBonusScale × 产球者攻击)
          × (1 + 产球者全伤害增加 DamageDealtScale)
          × (1 + 目标受伤倍率 DamageTakenScale)
```

- 产球者攻击按 `attackSource` 取物攻 / 魔攻 / 两者较高者（当前有效值，含 buff 与被动）。
- **不吃目标物防 / 魔防，不吃连携**（充能球是团队触发，不属于任何单卡的连携区间）。
- 伤害走统一的**伤害包管线**（`DamagePipeline`：`OnBeforeDamage` 可改数额、可完全抵消 → 写入 → `OnAfterDamage` 观测最终数额），
  写入方式与其它伤害一致（敌方写目标 ASC、玩家槽位转共享账本、账本目标一次结算）。
- 与 GAS 路径的差异说明：GAS `DamageExecution` 是 `Amount + 物攻 + Damage − 物防`；球伤害走定值通道
  （`CombatEffectExecutor.ApplyFixedDamage`），只做规则与写入。自 2026-09-19 统一后，三条通道的
  受伤倍率口径与规则管线完全一致（见本文 §1.3「伤害包管线」）。

> **2026-09-21 合并**：原 充能球规格 §3 的旧口径（把 `DamageDealtScale` 与 `DamageTakenScale` 写成**互相乘算**的两个因子，即 `× (1 + 增伤) × (1 + 受伤倍率)`）已由本文 §1.3「增伤与受伤增加一律加算，只有连携是乘算」取代。现行口径：
>
> ```
> 最终伤害 = base × (1 + Σ增伤 + Σ受到伤害增加) × (1 + 连携加成)
> ```
>
> 即把上面公式里的两个 `(1 + …)` 因子**合并进同一个加算桶**：`单球伤害 = base × (1 + DamageDealtScale + DamageTakenScale)`（`OrbDamageScale` 球伤害增加同桶，可带元素掩码，见 §14.11.1）；充能球不吃连携，连携因子恒为 1。`base = perOrbAmount + attackBonusScale × 产球者攻击`，攻击取值、不吃物/魔防、伤害包管线三项不变。

### 11.4 回合结束产出（原 §4）

每个回合结束固定产出 **1 个四属性球 + 1 个物理/魔法球**：

- 统计口径 = **本回合打出的卡牌**（含空放；卡牌结算入口登记，回合结束取走并清空）。
  - 四属性球：按卡牌**自身 `element`** 计红/蓝/绿/黄出现次数，取最多者。chalux 被动2 的"注入红"**不**计入（统计只认卡面属性）。
  - 物理/魔法球：按卡牌 `cardType`（`Physics` / `Magical`）计数，取最多者；其它类型（Support/Healing/Curse…）不计。
  - 平局或本回合未打出任何卡牌：各在自己那一组里**随机**（走 `combat.orb` 独立随机流，同种子可复现）。
- 产出顺序固定：先四属性球，后物理/魔法球。
- **产球者**（回合结束产出的球）：
  - 四属性球 = 全队 `max(物攻, 魔攻)` 最高者；
  - 物理球 = 全队物攻最高者；魔法球 = 全队魔攻最高者；
  - 按当前有效值判定，并列取**槽序最小**（确定性）。

## 12. 弹珠阶段与轮值普攻（2026-11-23 取代原自动普通攻击）（原 普通攻击规格 §1–§10）

> **原规格**：`2026-09-20-normal-attack-design.md`（已归档）与 `2026-11-23-marble-phase-design.md`（已并入并归档）。
> **原关系**：服从 [2026-05-11 总规格](2026-05-11-kemo-card-design.md)；伤害维度与充能球（见本文 §11）共用同一套标注。
> **段号对应**：§12.1–§12.10 保留原普通攻击规格的段号位置，便于旧引用定位；内容已按 2026-11-23 弹珠阶段重写。

### 12.1 机制概述与系统关系

- 回合结束进入 **弹珠阶段**，用本轮累计的 `Count` 替代原「自动对敌方全体的一次普攻」。轮值角色仍由回合数决定，`Count` 的分配结果才是每个目标的伤害包。
- **弹珠轮值普攻不是打出牌**：不触发卡牌 / 固定手牌槽的出牌钩子，不计入连携人头与充能球回合产出的卡牌分布统计，不消耗能量、不可取消；被封印角色仍会轮值（封印只限制出牌与主动技）。
- **充能球（Orbs）**：暂时保留，与弹珠系统并存；是否移除 / 合流待弹珠原型与实测后再评估。
- **卡牌直伤口径**：后续计划统一为「无视防御」；弹珠阶段的轮值普攻 **继承原普攻口径，计算目标防御**。该调整落地前，卡牌与普攻仍按各自现行公式。
- **失效 / 待重做**：原自动全屏轮值普攻、固定手牌槽相关效果、旧元素连携、批量出牌前后钩子等与即时出牌 / 弹珠阶段冲突的机制停用，后续随角色与卡牌重做统一替换（见 §9 与总规格开放项）。

### 12.2 阶段流程与操作权限

1. **出牌阶段**：战前按角色配牌；战斗中共用抽牌堆、墓地与 10 张手牌上限，出牌由所属角色支付能量。卡牌可造成伤害、积攒增益、修改盘面 / 撞钉属性，或向待发队列添加弹珠。出牌期间清波沿用即时出牌规则，当前效果结清后换波或判胜；已加入本轮待发队列的弹珠与盘面改动保留至本回合弹珠阶段。
2. **进入弹珠阶段**：玩家点击「结束回合」（原「结束出牌」）且当前效果结清后进入，锁定本轮轮值角色：
   - **轮值公式**：`(TurnNumber - 1) % 队伍人数`；出牌阶段清波且保留当前回合时 `TurnNumber` 不变，轮值不变。
   - **封印**：被封印角色仍正常担任本回合轮值普攻角色（封印只限制出牌与主动技）。
   - 三人共用同一盘面；本轮全部弹珠（含队友卡牌 / 技能添加的）均归属轮值角色。本轮 `Count` 从 0 开始；队列与场上均无弹珠时直接跳过发射进入结算。
3. **阶段内操作权限（含主动技与消耗品）**：
   - 可进行：瞄准 / 取消瞄准 / 发射、切换敌方标记、切换飞行倍速、提前结束、暂停，以及 **释放主动技与使用消耗品**。
   - 部分技能与消耗品带阶段 / 状态条件；不满足时禁止使用并拒绝请求，不消耗资源。
   - **阶段内效果过滤**：弹珠阶段成功释放的技能 / 消耗品中，修改卡牌费用、抽牌 / 加手牌、补能等仅服务出牌阶段的效果 **空过**；只有改变战斗属性（加攻、增伤、护盾、治疗、敌方减益等）、直接伤害、加球或改盘面等对当前及后续战斗有效的效果正常生效。
   - **实时联动**：操作若改变双方属性、血量、嘲讽或导致敌人死亡 / Boss 破条，须立即刷新血条扣血预览、标记合法性与提前结束资格；若敌方全灭，立刻中断当前飞行并按清波 / 判胜逻辑结算。
4. **发射、入队与多球同屏**：
   - **待发队列**：FIFO。场上无活跃球时，玩家调整角度发射并消耗队首 1 颗；取消瞄准保留待发球。入队加球追加到队尾，界面按顺序展示球属性。
   - **场上生成 / 多球同屏**：`ActiveBalls` 支持分裂或命中效果直接生成新球；场上同时活跃弹珠 **上限 20**（超过则抑制或按效果降级）。由撞钉触发分裂时，新球生成瞬间将该钉记入自身 `ContactedPegIds`，避免第 0 帧原地重复计分。
   - 全部活跃球离盘或因困球回收后，先结清回收触发；若队列仍有球，进入下一颗的瞄准与发射。
5. **普攻结算与回合推进**：队列与 `ActiveBalls` 同时为空，或玩家提前结束时，锁定最终 `Count` 并执行分配与伤害结算；完成基础普攻、追打及派生效果后进入结算阶段（`CardExecution`）、敌方阶段、换波或判胜。零 `Count` 跳过伤害与命中触发。回合结束时的 Buff `Turns` 递减仍在弹珠结算完毕且敌方阶段之后统一执行。

### 12.3 归属与轮值

```
槽位索引 = (TurnNumber - 1) % 队伍人数
```

- 回合计数用全场累计 `TurnNumber`（不随换波清零）；取模基数为队伍实际人数（当前 3）。
- 纯函数口径见 `NormalAttackRuntime.ResolveSlotIndex(turnNumber, characterCount)`。
- 被封印角色仍正常轮值（§2.5）。
- 出牌阶段清波且保留当前回合时，轮值角色不变；回合结束后清波进入下一个正常玩家回合，按新回合的 `TurnNumber` 轮值。

### 12.4 盘面、物理与计分

- **独立逻辑坐标与固定步长**：盘面使用与分辨率无关的逻辑坐标（界面等比映射），纯 C# 无头推进，固定 **1/60s**；禁用引擎渲染帧与原生物理节点。
- **空间拓扑**：竖向二维重力场；顶部与左右三面墙反弹，**底部开放**（球完全越过底界即离盘）。
- **发射口**：悬空于顶部下方，留出至少大于最大球半径及保护距离的空间；固定发射速率，玩家只调整角度，**不限制角度**。发射口与初始出射路径留保护区，撞钉不得覆盖。
- **速度与碰撞**：基础撞钉 / 墙壁碰撞有轻微动能损失（恢复系数 < 1），预留碰撞增能接口；有最高速度钳制与单步连续碰撞迭代上限。
- **固定布局**：开战放置 **4 枚固定撞钉**；每轮基础发放 **2 颗弹珠**。撞钉布局及「本场战斗持续」效果跨回合、跨波继承；换波不重置盘面；重置盘面通过后续专属技能 / 效果原语（如 `ResetMarbleBoard`）接入 Boss 出场或切条。
- **多球**：活跃球之间默认互不碰撞（相互穿透），仅与墙壁和撞钉碰撞；每颗球独立维护位置、速度、半径、点数、`ContactedPegIds` 与困球计时。
- **计分**：每次有效撞钉接触增加 `弹珠点数 × 撞钉点数` 的整数 `Count`；墙壁反弹不计分。持续贴合去重：中心距 `<= r_ball + r_peg + eps` 且钉 ID 不在集合内时计分；仅当后续物理步严格 `> r_ball + r_peg + detachMargin` 才移出。同一步同时接触多枚不同钉各计一次。
- **瞄准预测**：读取发射前盘面快照，按真实 1/60s 步长复用实弹的重力、碰撞、擦边容差与同时接触规则，跳过命中效果与随机数；路径按折返累计至显示上限或离盘截断，并绘制首次碰撞落点。飞行中变径 / 增钉 / 合并会使实弹偏离预览；下一颗待发射时按最新盘面重算。

### 12.5 撞钉合并与球位合法化

- **触发**：膨胀导致两枚及以上撞钉圆盘重叠时合并；恰好相切保留。
- **几何与点数**：合并后点数为各钉之和；中心按面积加权平均；半径取 `min(最大半径, √Σr²)`；同时重叠的一组一次合并，若新钉继续重叠则连续合并至稳定，新钉圆心 / 半径受三面墙裁剪。
- **附加效果**：合并后新钉 **最多保留 1 份**附加效果（含剩余次数 / 期限）。优先保留主钉（半径最大；平手点数高；再平手生成序号早）的效果；主钉无效果时按同优先级从其它被合并钉中选 1 份。
- **球位合法化**：合并本身不计命中。连锁合并稳定并完成墙壁裁剪后，若活跃球落入新钉内部，沿最近且优先朝向非墙壁自由空间的法线移出并做墙壁裁剪；同时将新钉加入该球 `ContactedPegIds`，待严格脱离后再接触才计分。

### 12.6 提前结束与困球回收

达到下列任一条件即可提前结束（包括多球飞行期间）；按钮点亮后仍可继续发射或等待弹跳积累 `Count`。按钮不可用时，悬停展示未满足原因：

| 条件 | 判定 |
|---|---|
| 当前伤害已足够 | 按当前标记、嘲讽约束与伤害分配预演，全部普通敌人都会死亡，且每个 Boss 都会死亡、已受换条保护或将在本次结算触发换条保护。仍有普通敌人能存活时继续检查时长条件。 |
| 本阶段达到时长门槛 | **从本阶段第一颗球实际发射后**开始累计有效游戏时间（含后续瞄准与飞行，暂停停表）；首轮门槛 12 秒（`MarbleEarlyEndTicks`，可调）。达到后按钮持续可用。 |

- **境界一致性**：点击结束时，在 1/60s 物理步边界结清该步全部命中，再核对结束资格、回收全部活跃球、放弃剩余待发球并锁定最终 `Count`。手动结束与最后一球离盘同时发生时只结算一次。飞行途中若因撞钉效果 / 技能 / 消耗品导致敌方全灭，立刻中断、回收并按清波 / 判胜结算。
- **困球回收**：弹珠不设生命周期，允许无限反弹。每颗球独立监测：连续约 **3 秒**几乎无移动即认定困球（结合位移、实际行进距离与观察窗口活动范围，区分高速往返与缓慢持续运动）。接近阈值（约 1.5 秒）时界面给出微弱闪烁 / 进度环提示；恢复有效运动即重置，暂停停表。回收保留已得 `Count`，先结清退场触发，再处理剩余球或阶段结束。

### 12.7 轮值普攻伤害与追打

- **类型**：轮值角色 `PhysicalAttack` 与 `MagicAttack` 较高者决定 `Kind`（平手物理），附带角色全部 `Element`；结算时扣目标对应的 `PhysicalDefense` / `MagicDefense`。
- **基础伤害**：对每个分到 `Count` 的目标，`max(0, Count × 攻击力 × NormalAttackScale − 对应防御)`，再乘加算倍率桶：
  ```
  × (1 + DamageDealtScale + NormalAttackDamageDealtScale
       + 目标 DamageTakenScale + 目标 NormalAttackDamageTakenScale)
  ```
  不吃卡牌连携。经统一 `DamagePipeline` 处理规则减伤与护盾抵扣后写入敌人生命（弹珠普攻启用目标护盾 1:1 抵扣）。
- **`NormalAttackCount`**：自身为轮值角色时，本轮基础发射球数 `+N`（进入弹珠阶段时按该属性追加待发球）。
- **追打 `trait.follow_up`**：非轮值队友持有追打时，最终 `Count` 锁定并完成分配后，先结算轮值角色基础普攻，再对每个分到 `Count` 且 **仍存活且未处于换条免疫** 的目标追加 `Count × 追打者攻击力 × 追打%`；按追打者自身物 / 魔判定、全部元素与目标对应防御结算，应用普攻加算倍率并走 `DamagePipeline`。多个追打取最高百分比；轮值角色自身不触发；已被基础普攻打死或已触发换条保护的目标跳过。
- **`NormalAttackShieldGainScale`**：按本次弹珠普攻实际造成的敌方生命损失转化护盾。
- **辅助转化预留**：治疗 / 辅助角色把 `Count` 转化为治疗或团队增益的机制留待后续重做。

### 12.8 嘲讽约束、Count 分配与预览

- **标记受嘲讽约束**：敌方存在正 `Taunt` 时，玩家只能在高嘲讽的存活可受伤敌人之间切换标记；进入弹珠阶段自动默认标记最高者（并列按站位）。无嘲讽时可自由标记合法可受伤敌人。
- **分配算法**（预览与实弹共用同一套无副作用完整伤害管线）：
  1. 优先处理玩家标记且可受伤的目标。足以击杀时只分配所需的最小整数 `Count`（Boss 以当前血条为止）；完全免疫或换条保护目标跳过。
  2. 其余目标优先选择可击杀且所需 `Count` 最少者；都无法击杀时选择用剩余 `Count` 预计造成最多实际扣血者；平手按敌方站位。分配量从本轮余额扣除。
  3. 血条显示用**当前已得 `Count`** 立即结算时的预计扣血；命中、改标记、释放技能 / 使用消耗品或攻防状态变化后实时刷新。最终结算复用同一算法，锁定基础普攻结果后再处理追打、击杀等派生效果。
- **示例**：每点 `Count` 对应 10 点物理攻击，敌人 A 有 18 血、B 有 70 血（无防无盾）。6 `Count` 自动分配时 A 得 2、B 得 4；标记 B 时 B 得 6、剩 10 血。若 A 另有 5 点护盾，击杀 A 需要 3 `Count`。
- **超额与剩余记录**：保留 **总 `Count`、已分配 `Count`、剩余 `Count` 与剩余原因**（普通敌人全灭、Boss 换条保护等），供后续超杀机制使用；剩余 `Count` 不跨波继承，下轮从 0 累计。最后一个整数 `Count` 的溢出伤害单独记录。

### 13.1 BuffInstance 运行时（原 Buff 系统死代码的实装）（原 §1）

原 `BuffDto`/`buffRefs` 只做内容校验、不参与战斗（`CombatEffectExecutor` 对 ApplyBuff/RemoveBuff no-op）；`HandSlotEffectRef` 为占位。本设计把 buff 实装为**被动/增益/减益/槽位效果的唯一载体**。

#### 13.1.1 数据（BuffDto 扩展）（原 §1.1）

- `modifiers`: 属性修正列表（镜像 GE modifier：attributeId / op(Add|Multiply|Divide|Override) / magnitude(Scalar|SetByCaller)），幅度 × 层数。
- `conditions`: 持有者条件（**2026-09-26 统一为战斗条件列表**，与 `EffectDto.conditions` 同形）：空列表 = 无条件常驻；
  不满足时 buff 休眠（不参与属性聚合、不显示图标、不触发钩子）但不移除。条件主体 = **持有者**。
  所有「某属性 / 某种族特殊加成」一律用通用条件 `IdentityMatch`（见 §14.7），不再为每个效果单写条件。
  **描述约定（2026-09-25）**：效果描述里的 `·` 一律表示**或**（`raceAny` / `elementAny` 列表内取或，跨维度默认也取或）；
  只有描述里**显式写「且」**时才用 `matchAll: true` / `raceAll`。
  `raceAll` 在列表内取**"且"**（持有者必须同时带全部列出的种族），`matchAll` 只对**已配置**的维度取"且"
  （未配置的维度不参与判定）。
- `chainElementInject`（**2026-09-26 参数化**）：连携属性注入规则 `[{ from?, add }]`——打出 `from` 中任一属性的卡
  （`from` 缺省 = 任意卡）时，该卡在连携统计里额外计入 `add` 的属性。见 §13.3。
- `applyScope`: `Self`（默认）/ `AllAllies`（团队型被动挂到每个队友）。
- 钩子节点：`onApply / onTurnStart / onTurnEnd / onStackChanged / onRemove / onWaveStart / onActiveSkillCast / onSlotCardPlayed`，
  以及后批扩展的 `onCardSettled / onCardExecutionEnd / onOrbTriggered`（§14.11.1）与 `onDamaged`（§14.8.5，2026-09-25）。
- `onTurnStart` 效果参数支持 `turnInterval: N`：按**波内回合计数**每 N 回合触发一次。
- 钩子效果目标解析：`hookTargets`（self 缺省 / team / allies / randomEnemy / allEnemies）与 `targetFilter`（**2026-09-26 统一**：`self` / `excludeSelf` 两个硬约束 + `condition`（一条战斗条件，主体 = 候选）；旧扁平键在运行期保守回退到 [来源]、准入阶段报错，见 §14.7），按**单个效果引用**的合并参数（效果参数 + 实例挂载参数）解析。
  `hookTargets: "allies"`（2026-09-25 新增）= **全部玩家角色逐个**（与 `team` 的区别：`team` 是队伍共享账本，
  只用于治疗/队伍级效果；`allies` 是逐槽位，用于"己方全体"的抽取/增益类投放）。
  - **描述约定（2026-09-25）**：筛选维度**默认取"或"**——效果描述里的 `·` 表示或（如「红属性·人类·学术」= 红 或 人类 或 学术），
    在 `IdentityMatch` 的参数里即"跨维度默认取或"；只有描述里**显式写「且」**时才用 `matchAll: true` 取"且"。
    `raceAll` 仍是**列表内取"且"**（"同时具备多种族"的显式且，如「人类且学术」）。
  - `excludeSelf: true` 剔除来源自身（「自身以外的…角色」）。两键缺省关闭，缺省行为与旧内容完全一致。
  - **`hookTargets: "team"`（2026-09-24 新增）** 解析为队伍共享账本 `CombatTargetRef.PlayerTeam`：规格 §1.3 的**玩家侧治疗只认账本目标**（点名槽位会被 `RejectSlotHealTargets` 软失败剔除），因此"钩子/被动给全队回血"必须用它；队伍级（账本口径）的其它效果同理。

> **2026-09-21 合并**：钩子节点表在后批扩展里新增了 `onCardSettled` / `onCardExecutionEnd` / `onOrbTriggered`，并给钩子效果加了 `oncePerTurn` 参数；见 §14.11.1。

> **潜能被动统一为 4 档：0 / 10 / 30 / 50（2026-09-24）**：原六档方案里的 **70 与 99 两档连同其载荷（buff / 效果 / 文案）整体删除**——不是把两条被动合并进一个 buff。五个角色因此统一为 4 条被动、档位一律 `0/10/30/50`。
> 被删除的机制（如需回归须重写内容）：克鲁克斯的全伤害增加 25%（原 P5）与"主动技后敌方全体防御归零 + 自身 +3 能量"（原 P6）；莱因哈特的普攻伤害 +50%（原 P5）与"主动技后随机手牌费用 0"（原 P6）；巴赫的"本回合打出 X 张牌 → X-1 个绿球"（原 P5）与"主动技后自身攻 +30"（原 P6）；冯·诺依曼的"黄计入蓝连携"（原 P5）与"主动技后随机敌人行动计数 2"（原 P6）。
> 引擎侧能力**全部保留**，只有 3 项暂时没有内容投放：`slot.free_cost`（§14.8.2）、`NormalAttackDamageDealtScale`（§14.6.3）、`GainOrbPerPlayedCard`；`SetActionCount`（§2.1）与 `AttachSlotBuff` 仍有内容在用（前者由图灵 P2/P4 接管了"行动计数"这条控制轴，冯·诺依曼的角色线因此不再有该被动）。

#### 13.1.3 运行时（原 §1.3）

- 挂点三类容器：角色（含 ASC）、敌人（含 ASC）、手牌槽位（无 ASC，只承载钩子与 tag）。
- 修正经 `Aggregator.SetModifiersForHandle` 走与 GameplayEffect **同一条聚合管线**（Override 优先 → (base+ΣAdd)×ΠMul）。
- **条件休眠**：条件不满足 → 撤销句柄、不参与聚合、不触发钩子、UI 不显示；**不移除**。每回合开始重估，持有者属性/种族变化下一回合自动切换。休眠/移除后必须 `RecalculateAll`。
- **时长**：`durationType: Turns` 由 BuffRuntime 在回合结束统一 tick（先 onTurnEnd → 递减 → 到期 onRemove → 移除），覆盖角色/敌人/槽位全部容器（角色/敌方 ASC 回合钩子的历史缺口由本层接管）。
- **快照语义**（2026-09-19 评审修正）：钩子分发一律在容器**快照**上枚举——钩子可能对自己的容器挂/删 buff，活列表枚举中修改会抛异常。回合结束以触发前快照为本回合基准（钩子期间新增的 buff 本回合不 tick）；到期补发只对**仍持有**的实例触发 onRemove（先被驱散的不双触发）。
- 叠层：Add（至 MaxStacks；**`Turns` 型下每层独立计时**，新层拿完整时长、先挂的层先到期，层数脱落时重算属性修正）/ Refresh（重置时长，保持层数）/ Replace（移除重建）；互斥组 exclusiveGroup 先删后挂。
- 开战被动：`RunController.StartBattle` 按各角色**全部被动**（槽序 + 定义顺序）构造 `BattleStartBuffEntry`，在 BattleStart 管线中于技能注入之后、冻结 SharedHp 之前挂载。
- **敌人开战 buff（2026-09-20 接线）**：`EnemyDto.buffRefs` 声明的 buff 在 `RunBattleStart` 中（冻结 SharedHp 之后、`onWaveStart` 之前）逐敌挂到其自身，与玩家侧开战注入对称。此前该字段只做内容引用校验、从不生效。首个使用者是训练沙包「木桩」（`enemies/training_dummy.json` + `battles/training_dummy.json`：单波两个木桩、10000 血、每回合开始恢复 10000，无行动意图）。
  > 注：角色侧 `CharacterDto.buffRefs`（如 `kemo_talent`）仍是仅校验的旧通道，未接线（角色被动已统一走 `passives`）。
  >
  > **2026-09-21 合并**：角色侧 `CharacterDto.buffRefs`（常驻天赋）已于 2026-09-21 **整条移除**（原扩展规格 §3，归「内容与数据规格」）；**敌人侧 `EnemyDto.buffRefs` 保留**，与角色被动分属两条路径（见 §14.13）。

### 13.2 槽位效果（已停用：固定手牌槽移除）（原 §2）

> **2026-11-24 起**：固定手牌槽相关效果（槽位伤害、定时、充能、暴风、槽位费用归零等）已随即时出牌 / 固定手牌槽移除而停用；`AttachSlotBuff` / `DiscardSlot` 动作软失败空过。以下正文仅作为历史实现说明保留，现行战斗不投放这些效果。

- **槽位伤害**（`slot.damage` tag）：该槽打出卡牌时（`SettleQueuedCard` 结算前触发，含空放），对打出者造成参数伤害（玩家槽位 → 共享血量账本）。打出者持有 `trait.immune_slot_damage` 时跳过（chalux 被动1）。
- **定时**（`slot.timer`，2026-10-09）：敌方对角色指定或随机手牌槽投放 `Turns` buff，实例 `timerTurns` 为初始回合数、`amount` 为伤害量。己方回合结束减 1，归零时移除并造成定值伤害，再向左、右相邻槽扩散；边界不环绕。扩散沿用初始回合数与伤害量，并在之后每次到期继续扩散。已有有效定时的槽保留原实例、剩余时长与伤害，不覆盖、不叠加。空槽也能持有定时，牌的打出与换入不影响倒计时。
  - 全体容器先按同一快照递减并移除到期者，再由 `SlotTimerRuntime` 结算和扩散，因此同时到期的定时各引爆一次，新扩散实例从下一回合才递减。
  - 定时伤害是槽位自结算，吃持有者全伤害减免和统一伤害规则，不加攻击力、不吃卡牌连携，也不记作敌方攻击或触发受击成长。驱散/替换移除不引爆；`trait.immune_slot_timer` 在投放与引爆时拦截定时伤害和扩散，不影响充能。
  - `AttachSlotBuff` 新增 `slotSelection: "random"`（含空槽）；敌方来源时作用于传入的玩家角色目标，玩家来源仍按来源自身投放。出货敌方技能 `slot_timer_attack` 演示随机一槽、3 回合、30 伤害，可由敌人技能引用；本次不改既有敌人的技能表。
- **充能**（`slot.charge` tag）：实例参数 `charge`（罗马序号计数，充能 I = 1）。该槽每打出一张牌计数递减，归零触发 `onSlotCardPlayed` 载荷并**重置计数**（持续期内可反复触发）；到期移除前不因触发消失。chalux 专属卡「绝念」用同一机制投放**充能 II**（`charge: 2`，见本文 §11.7）。
- **充能互斥（2026-09-21 决议）**：同一手牌槽**只允许存在 1 个充能**。新的充能**无条件覆盖**旧的，并**重置进度**：
  - 覆盖无视 id 与 `stackRule`——即使新旧完全同 id、即使写下的是 `Refresh`/`Add`，也是"移除旧的 + 新建实例"，不会叠层、不会保留已积累的计数；
  - 覆盖时对旧实例补发 `onRemove`（与驱散/到期路径同口径）；
  - 实现位置 `BuffRuntime.StackOrAdd` 的最前置分支（`RemoveExistingCharges`），因此槽位与角色容器的充能投放走同一规则。
  - 语义理由：充能是"这一槽当前在读哪个序列"的唯一状态，允许并存会让"归零触发"的判定与玩家预期脱节。
- 载荷示例：`{kind: Damage, params: {amount: 12, damageGameplayEffectId: ..., hookTargets: "randomEnemy"}}`；DamageExecution 本就加 100% 源物攻，因此"12+100%物攻"即 `amount: 12`，元素（蓝）仅为 damageType 标签，不参与数值。
- **槽位 buff 的投放通道**：技能动作与同名效果 `AttachSlotBuff` 支持显式 `slotIndex` 或 `slotSelection`（`randomNonEmpty` / `random` / `all`）；`slot.free_cost` 见 §14.8.2。
- **暴风**（`slot.storm` tag，2026-09-23 新增，冯·诺依曼套件）：该槽打出卡牌时（与槽位伤害同一时点，含空放），把**附近手牌槽**的牌吹散（弃置，进持有者弃牌堆）。
  - 扩散范围取首个效果引用的 `adjacentSlots`（缺省 1 = 1 个相邻槽）；选槽顺序**先左后右、由近及远**，不含该槽自身（5 槽下槽 2 的 2 个相邻槽 = 槽 1、槽 3；3 个 = 槽 1、槽 3、槽 0），实现 `BuffRuntime.StormNeighborSlots`。
  - 运行时对每个相邻槽各触发一次 `onSlotCardPlayed` 载荷，并把该槽索引并进效果参数 `slotIndex`；载荷通常是 `EEffectKind.DiscardSlot`。
  - **只弃未标记的牌**：已入队/已确认的牌保留、标记也不清除（规格 §2.2"其它通道"不得借弃牌回滚确认态），实现 `CharacterBattleInstance.DiscardSlotCard`。
  - 免疫特征 `trait.immune_slot_storm`（冯·诺依曼 被动1）使该角色的手牌完全不被吹散——只抵消暴风本身，槽位伤害/充能不受影响。

### 13.3 连携（已停用：首版关闭）（原 §3）

> **2026-11-24 起**：旧元素连携的计算、加成及依赖档位的触发在首版关闭；以下正文保留为历史实现说明，待重新设计即时出牌下的连携后再启用。`ChainTierAtLeast` 等条件在连携关闭期间不满足。

- 出牌是"标记 → CardExecution 统一结算"批处理：**结算阶段开始**按完整出牌队列一次性统计各属性的**不同角色数**（同一角色多张只计 1 人），档位作用于**本回合全部**该属性伤害/治疗卡——无次序、无首角色惩罚、无回溯。**统计侧与加成侧口径不同（2026-09-21 修正）**：统计侧统计队列里的**所有**卡——Support / Curse 等非输出卡同样把打出它们的角色计入人头；加成侧只作用于连携适用的卡牌类型（Physics/Magical/Healing），即非输出卡堆人头但不吃加成。

- 加成注入：结算单卡时设 `simulation.CurrentChainBonus`（try/finally 归零，卡牌上下文之外恒 0）；GAS 路径经 SetByCaller `ChainBonusScale`，直伤/治疗路径直接缩放。
- **加算规则（2026-09-21 修订）**：`伤害 = base × (1 + Σ增伤 + Σ受到伤害增加) × (1 + 连携)`——**增伤与受伤增加一律加算，只有连携乘算**（权威表述见本文 §1.3）。**三条伤害通道（GAS 公式 / 直伤定值 / 充能球）共用同一套缩放与伤害包管线**（2026-09-19 统一），通道差异只在 `base` 怎么算。治疗 = `(amount + 源 HealPower × healPowerScale) × (1 + 连携)`，不受增伤影响；`healPowerScale`（2026-09-25）控制源回复量占比，缺省 1（全额），`0` = 不吃回复量（「回复 12 + 0% 回复量」）。`MagicAttack` / `MagicDefense` 的消费公式已于 2026-09-21 落地（GAS 通道 `damageType: "Magical"` → `魔攻 − 魔防`，见 §14.5）。
- **连携属性注入（2026-09-26 参数化）**：buff 声明 `chainElementInject: [{ from?, add }]`——打出 `from` 中任一属性的卡（`from` 缺省 = 任意卡）时，该卡在统计上额外计入 `add` 的属性。
  典型：克鲁克斯 被动2 `[{ "add": ["Red"] }]`（红卡计入红）；「黄计入蓝」= `[{ "from": ["Yellow"], "add": ["Blue"] }]`。
  配 `applyScope: AllAllies` 即全队生效；多条注入在 `ChainCalculator.CardElementFlagsForCount` 内合并，**只影响人头统计**，加成侧仍按卡牌自身属性取档。
  旧 tag `trait.chain_inject_red` / `trait.chain_yellow_counts_blue` 已删除（能力保留、写法参数化）。

### 14.6 普通攻击扩展（原 §6）

以下三项全部**只作用于弹珠阶段的轮值普攻**（本文 §12）：

#### 14.6.1 普攻次数（`NormalAttackCount`）（原 §6.1）

- 属性改为 **增加本轮基础发射球数**：自身为本回合轮值角色时，进入弹珠阶段按 `max(0, NormalAttackCount)` 追加待发弹珠（基础 2 颗 + N）。
- 该属性默认 0，buff 用 `Add` 叠加；不再有"多次执行整轮普攻"的旧语义。

#### 14.6.2 追打（`trait.follow_up`）（原 §6.2）

- 持有者**不是**本回合轮值角色时，在最终 `Count` 分配完成后，对每个分到 `Count` 且仍存活、未处于换条免疫的目标追加一次伤害。
- 数值口径：`Count × 攻击力 × percent × NormalAttackScale − 目标对应防御`；带攻击者元素、走同一伤害包管线、不吃连携。
- **多个追打只取最高值**（不同 buff 定义；出货内容用 `follow_up_1/_2/_4` 表达不同时长）。
- 轮值角色自己持追打**不重复出手**；已被基础普攻打死或已触发换条保护的目标跳过。

#### 14.6.3 普攻专属倍率（原 §6.3）

| 属性 | 作用 | 位置 |
|---|---|---|
| `NormalAttackDamageDealtScale` | 攻击者：弹珠普攻伤害 `× (1 + 本属性)`，与 `DamageDealtScale` 同桶加算 | 攻击侧 |
| `NormalAttackDamageTakenScale` | 目标：被弹珠普攻时 `× (1 + 本属性)`，与 `DamageTakenScale` 同桶加算 | 受击侧 |

卡牌伤害两者都不吃——这正是"受到的普通攻击伤害 +25%"与"自身普攻伤害 +50%"必须与全伤害增加区分的原因。

#### 14.6.4 可观测（原 §6.4）

`NormalAttacks.LastMarbleSettlement` 记录本轮弹珠结算：总 / 已分配 / 剩余 `Count`、剩余原因、逐目标分配（基础伤害、护盾吸收、生命损失、溢出、追打、剩余生命、是否破条 / 进入保护）。预览使用同一结构且不写结算记录。

### 14.7 Combat 条件域启用（原 §7）

`ICombatCondContext` 从空占位变为可用上下文（`TurnNumber` / `TurnsIntoWave` / `SourceCharacterIndex` / `CountCardsPlayedThisTurn`），由 `CombatCondContext` 在求值时构造。

- 新增 CondType **`CardPlayedThisTurn`**：参数 `{ count, elementAny? }`，判定"本回合该角色打出过 N 张命中指定属性的卡"（含空放，读 `CombatSimulation.PlayedThisTurn`）。
- **新增 CondType `ChainTierAtLeast`（2026-09-23，冯·诺依曼 被动2）**：参数 `{ tier, elementAny? }`，判定"本回合连携达到 N 档"——`tier` = 该属性参与人数下限（2/3/4 = 二/三/四连携档）。`elementAny` 缺省时按**当前正在结算的卡牌**的属性判定（多属性卡取各属性人头数的最大值）。为此 `ICombatCondContext` 增加 `CountChainParticipants(elementFlags)`，上下文数据源是 `CombatSimulation.CurrentChainCounts` / `CurrentChainCardElementFlags`（执行阶段开始时写入定档快照，离开单卡结算区间即清空，实现见 §14.11.x 的连携定档说明）。
- **新增 CondType `IdentityMatch`（2026-09-26，属性/种族统一的通用条件）**：参数
  `{ elementAny?, raceAny?, raceAll?, matchAll?, partyMinCount?, partyElementAny?, partyRaceAny? }`，
  判定**条件主体**的属性/种族身份与队伍人数门闩：
  - 主体来源：效果 `conditions` 缺省 = 来源角色；`targetFilter.condition` 逐候选；buff `conditions` = 持有者。
    为此 `ICombatCondContext` 增加 `SubjectElementFlags` / `SubjectRaceFlags` / `CountPartyIdentityMatches`。
  - 语义：列表内"或"、跨列表默认"或"（`matchAll: true` 取"且"、`raceAll` 列表内"且"）；
    队伍人数门闩与主体维度取"且"（只配人数时完全由人数决定），人数筛选自身维度默认取"或"。
  - **所有「某属性 / 某种族特殊加成」一律走这条**：buff 持有者条件、钩子/技能动作的目标筛选、效果条件三处
    共用同一份解析与判定（`IdentityFilter` + `CombatConditionEvaluator`），不再为每个效果单写条件/逻辑。
- `targetFilter`（2026-09-26 统一）：只保留 `self` / `excludeSelf` 两个硬约束 + `condition`（一条战斗条件，主体 = 候选）；
  原先扁平的 `elementAny` / `raceAny` / `raceAll` / `matchAll` 字段已删除。
  - 出现旧扁平键（或非法 / 空 kind 的 `condition`）时：运行期**保守回退到 [来源]**（绝不静默命中全队），
    内容准入阶段由 `ContentDefinitionValidator` 直接报错并剔除定义。
  - **槽位容器（手牌槽）没有持有者身份**：挂在槽位上的 buff 的 `conditions` 一律用容器自身 provider 求值
    （身份条件恒不满足 → 休眠），不按"所属角色的身份"求值（`BuffContainer` 类注释口径）。
- `EffectDto.conditions` 正式求值（AND，未知类型 / 参数非法 = 不通过）；内容准入阶段用同一套 parser 提前报错。
  buff `conditions` 与 `targetFilter.condition` 同样在准入阶段校验（写错只会让 buff 永远休眠 / 候选全部落选，必须拦下）。
- 接口刻意只暴露基础类型（属性位标志用 `int`），避免 `Frame.Condition` 反向依赖 `Frame.Content`。

> **钩子效果的目标选择器写在"钩子引用"上（2026-09-23 明确）**：`FireHook` 只把**引用参数**（`EffectRefDto.Params`）+ 实例参数交给 `hookTargets` / `targetFilter` 解析，
> `EffectDto.Params` 里的 `hookTargets` 不参与目标解析（`chalux_charge_glacial` 起就是这个口径）。
> 写完必须端到端跑一遍——写错位置时效果会落在**来源自身**上（伤害打自己），而内容校验不会报错。

### 14.8 新增取值与槽位机制（原 §8）

#### 14.8.1 `PartyCountScaled`（`EMagnitudeKind`）（原 §8.1）

`perCount × 队伍中命中筛选项的角色数`，筛选项为 `countElementAny`（元素）与 `countRaceAny`（种族）；两者都配时**默认取"或"**（描述 `·` = 或），需要"且"时写 `matchAll: true`。

- 人数统计**含自己**、**不封顶**、只算**已上阵**角色（队伍名单战斗内固定 → 最多 3 人）。
- 实现：`BuffContainer` 接受一个自定义取值委托（`CharacterBattleInstance.ResolveCustomMagnitude`），队伍查询由 `PlayerTeamState` 在组队时注入；buff 修正随回合开始的重估自动刷新。
- 「每有 1 名黄属性·动物角色，自身最大生命 +40」即 `perCount: 40` + 双筛选（3 人 = +120）。

#### 14.8.2 手牌槽费用归零（已停用）（原 §8.2）

#### 14.8.3 封印免疫（原 §8.3）

- 新特征 **`trait.immune_seal`**（与 `trait.immune_slot_damage` 同模式）。
- 实现：GE 挂上后 `GameplayEffectApplicator` 立刻摘掉授予 `combat.state.sealed` 的 Gameplay Effect——只抵消封印本身，同一 GE 的其它修饰/标签照常生效。

#### 14.8.4 嘲讽（`Taunt`）（2026-09-25 新增）

2026-10-09：敌人也可持有嘲讽。玩家单体与随机技能/卡牌在入队或主动释放前，只能从敌方最高正嘲讽目标中选取，并列均可选；界面高亮和指令校验共用 `CollectLegalTargetsForScope`。全体效果不受影响。已入队卡牌保留原本合法目标，目标死亡后的重选服从当前嘲讽池。钩子明确指定的随机敌人（如嘉极充能III）沿用钩子选择器，不改变为嘲讽目标。

- 新属性 **`Taunt`**（内容侧 `attributes/Taunt.json`；buff 用 `Add` 叠加，数值越高越优先）。
- 判定：敌方技能解析目标时，若合法目标里存在嘲讽值 > 0 的玩家角色，则**单体与随机**目标只从
  "嘲讽值最高"的那些角色里取（并列时按槽位序）；没有嘲讽者时按原规则（槽位序 / 随机）。
- 范围（`scope: All`）与队伍账本（`scope: Team`）**不受影响**——嘲讽吸引的是点名攻击，AOE 照常覆盖全队。
- 配套内容约定：**敌方攻击技能必须声明 `targetOverride: { side: "Enemy", scope: "Single" }`**
  （敌方视角的 `Enemy` = 玩家侧）。不写 `targetOverride` 会落到队伍账本（规格 §1.3 默认），
  没有具体受击角色，嘲讽与受击钩子都无从判定；`slime_tackle` 已按此补齐。
- **界面标识**：当前嘲讽值最高的队友打 Crosshair 准星（判定与落点见 Run 规格 §14.2「嘲讽 Crosshair」）。

#### 14.8.5 受击钩子（`onDamaged`）（2026-09-25 新增）

- 新钩子节点 **`onDamaged`**：持有者受到**敌方来源**的伤害时触发；中毒、手牌槽伤害等由持有者
  自身结算（`source == target`）的来源不计入。
- **批次语义**：一次敌方技能（`ExecuteEnemySkill`）为一个批次——批次内每次受击先记数
  （`DamagePipeline.NotifyAfter` → `CombatSimulation.RecordDamagedPlayerHit`），**全部伤害结算完**
  后按受击次数逐次触发钩子（`FlushOnDamagedHits`）。「受到 N 次伤害回复 N 次」即由此保证。
- **记数与"最终掉没掉血"解耦（2026-09-26）**：敌方攻击**命中**该槽位即记一次受击，即使护盾（§14.8.7）
  或减伤把最终伤害压到 0 也计入。因此「受到**攻击**后回复生命」与「受到**伤害**后获得护盾」在护盾吃满
  整击时都会触发；`DamageDealt` 表现事件仍只在最终伤害 > 0 时发射。
- 治疗落点：玩家侧治疗只认队伍账本（§1.3），因此"受击回血"的钩子引用必须写 `hookTargets: "team"`。
- 2026-10-08：受击账按每次命中保留攻击者；`onDamaged` 引用可声明 `hookTargets: "attacker"`，只对该次命中的存活攻击者反击，来源失效则空放。攻防公式把伤害压到 0 时仍记命中；显式 `AttackCount: 0` 不记命中。反击走普通魔法伤害公式，吃目标魔防和伤害倍率。

#### 14.8.6 队伍生命上限缩放（`TeamMaxHealthScaled`）（2026-09-25 新增）

- 新 `EMagnitudeKind`：`flat + floor(队伍生命上限 × ratio)`，**在 buff 实例创建时取值一次并缓存**
  （快照语义）：卡牌结算当场取数值，之后队伍生命上限变化不影响本实例（`BuffInstance._snapshotMagnitudes`）。
- 用于「物理防御 +1，并叠加队伍生命上限 3% 的数值（向下取整，仅在卡牌结算时取值）」。

#### 14.8.7 护盾（`Shield`）（2026-09-26 新增）

- 新属性 **`Shield`**（内容侧 `attributes/Shield.json`，默认 0、`allowNegative: false`）：**可消耗资源**，
  `GainShield` 增加 base 授予量；`AttributeAggregator.ConsumeCurrentValue` 在最终聚合值之后扣实际消耗。
  可用余额 = `max(0, 聚合额度 − 已消耗量)`，Add/Multiply/Divide/Override 或重复重算都不能补回已消耗的护盾。
  临时修饰被移除、额度缩小时，将消耗量裁到现有额度，避免给未来授予留下债务。可叠加、无玩法上限，战斗内永久，不随回合清零。
- **抵扣口径**：**1 点护盾抵 1 点伤害**。抵扣发生在伤害包管线**规则修正之后**
  （`DamagePipeline.RunBefore` → `AbsorbByShield`）：按 `min(当前护盾, 伤害)` 抵扣，护盾按实际抵扣量
  扣减，**余额才落到队伍共享账本**。
- **抵扣范围**（与 §14.8.5 受击钩子同口径）：
  - 只抵扣**点名玩家角色槽位**（`IsPlayerSlot`）的伤害——队伍账本（`scope: Team`）没有具体受击角色，
    不吃护盾（与「分槽护盾不吃账本目标」一致）；
  - 只抵扣**敌方来源**（`source.Side == Enemy` 且 `source != target`）——中毒、手牌槽伤害等由持有者
    自身结算的惩罚不吃护盾；
  - 范围（`All`）伤害逐槽结算，每个槽位各吃自己那一份护盾。
- **授予通道**：`GainShield`（`params.amount`）——技能动作与效果两条通道同源
  （`ESkillActionKind.GainShield` / `EEffectKind.GainShield`），效果通道供 buff 钩子使用
  （「红属性·动物角色受到伤害后获得 1 护盾」）。
- **界面**：护盾数值的展示（角色卡 / 血条）属**后置项**，当前只有属性可读，尚无 UI 消费方。

#### 14.8.8 致命保护与边界时长（2026-10-08 新增）

- `onBeforeFatalDamage`：规则修正与护盾抵扣后，点名玩家角色的剩余伤害达到当前队伍共享生命时，在生命写入前触发。可用 `oncePerCombat: true` 在效果条件与执行预算通过后登记一次门闩；回合与阶层切换均不重置。开战共享生命写锁期间不消耗致命保护。
- `trait.immune_damage` 抵消持有者的伤害；致命钩子授予该特征时，触发保护的伤害也被抵消。已持有免疫时不消耗护盾。免疫只保护点名持有者，不保护其他角色或未指定角色的队伍账本伤害。
- `durationType: UntilNextTurnStart` 在下个己方回合开始、规则/GE/Buff 开始钩子之前到期；回合结束不移除。本次开始钩子新授予的免疫保留到下一次回合开始。`durationType: Wave` 在下次阶层开始钩子之前移除。自然到期不受 `buff.undispellable` 限制，正常撤销属性修正并发移除事件。

## 16. 表现事件流（逻辑 / 表现分离）（2026-09-24）

**目的**：战斗逻辑（`Src/mod/combat`，纯 C#）与界面动画彻底分离。逻辑执行时**只记录事件**，不知道界面存在；界面事后取走事件、自行安排动画（如「角色移动到目标面前攻击再回来」），播完再与模拟器状态对账。

### 16.1 逻辑侧契约

> **2026-11-24 阅读提示**：即时出牌起，`CardSettleStartedEvent` / `CardSettleEndedEvent` 仍用于单张牌的即时结算；旧「队列标记 / 确认 / 取消退费」相关描述已失效。弹珠运行时可返回撞钉命中 / 离盘 / 困球事件（`MarbleStepResult`），当前实时推进使用轻量 `StepPhysics` 不构建逐步事件，界面逐帧读取球位置；后续若接入逐步表现，应在 `StepPhysics` 结果中恢复事件收集。

2026-10-11：玩家阶段支持 `UseConsumableCommand`，库存与 Run 共用 `CombatItemInventory`。校验拥有该物品及合法目标后消耗并执行 `useSkillRefs`，不扣能量、不占行动、不触发主动技能钩子；结算后的损血 / 治疗 / Buff 继续走既有表现事件，播放锁同其他指令。遗物开战技能在 InitialBuffs 后、冻结生命前执行，Buff 由技能安装。

- `CombatSimulation.Presentation`（`CombatPresentationLog`）**始终存在**（不是构造参数）；`Emit(event)` 追加，`Drain()` 取走并清空，`Count` 只读。
- 事件类型全部是 `Src/mod/combat/presentation/` 下的 **不可变 record**，**只携带值**（索引、id、数值、`CombatTargetRef`、`BuffHolderRef`），**不得**持有 `EnemyUnit` / `CharacterBattleInstance` / `BuffInstance` 等运行时对象引用，也**不得**引用 Godot 类型。
- 发射点只允许在**已有编排层**插入一行 `Emit`，不改变玩法顺序与数值；单测 `CombatPresentationLogTests` 守卫事件顺序。
- 事件是**记账**而非回放：同一状态变化只发一次；界面按事件增量播放，播完以 `SyncFromState` 为准，事件缺漏不会导致界面与逻辑不一致。

## 2026-10-06 结算边界与实现契约补充

本节明确既有机制在组合场景下的边界，不改变增伤、连携、能量与多波玩法公式。

- **合法构筑开战**：Run 的 `CardCollection` 必须传入战斗工厂，开战与卡组编辑使用相同的拥有权集合。注册但未获得的通用卡仍不能使用。战斗期间的卡组锁覆盖已捕获的 DeckPreset 引用与快照替换入口。
- **共享生命持久写入（2026-10-11）**：伤害、治疗、开战补满与上限裁剪同步账本的基础值与当前值，回合结束/效果移除的属性重算不能恢复已经扣掉的生命，也不能复活已阵亡队伍。
- **统一损血口径**：Damage execution 把未按生命余额截断的计算数额交给宿主；经规则、护盾后才写生命。`OnAfterDamage`、DamageDealt 表现与伤害返回值使用实际损血，超额伤害单独计数。敌方命中玩家槽位时，完全吸收也记一次 onDamaged；零实际损血不广播正数伤害事件。兼容 Instant Health 修饰符的转移边界只包住数值写入，生命周期钩子在边界外分发。吸血只累计本 GE 各次结算返回的实际损血，不纳入 onApply 等钩子的独立伤害或治疗。直伤回落继续传递完整 kind/element，保证缩放、规则、表现与受击账一致。
- **回合边界**：首回合和后续回合均依次执行规则 OnTurnStart、GE 开始批次、Buff 开始批次，再检查终局/换波。终局后不灌入玩家资源、不覆盖终局阶段。每回合收尾只运行一次，先运行规则、GE/领域、Buff 和回合产球；即时出牌不携带跨回合的标记或预付费用。
- **GE 驱动**：队伍、玩家角色与存活敌人的 ASC 都参与回合开始/结束，持续 GE 到期、周期 Damage execution 和 apply/stack/remove 钩子均有接线。来源身份在施加者死亡或换波后仍保留。v1 敌方队伍账本载荷仍为空放。
- **重入与快照**：每次回合/波次的 GE 或 Buff 批次先快照该模型的全部持有者，再执行；批次内新增实例留到下一批，同一批次已被移除的实例不再触发钩子、tick 或注册修正。移除先撤销容器/句柄再发 onRemove。Buff 替换先提交冲突移除与新实例，再发旧实例 onRemove；重入投放以最后一次提交为准，新实例仍存在才发 onApply。领域先发布所属槽位再发 onApply；替换的新领域不在旧领域的回合结束批次扣时长。单卡与球批次上下文使用作用域恢复；嵌套球的逐球效果遮蔽外层批次，内层钩子结束后恢复外层。
- **目标边界**：出牌和主动技在扣费前验证合法性、数量与唯一性。Self/Team 可省略自动目标；All 可省略或提交完整合法集合；Single 在有合法目标时必须恰好指定一人；RandomN 可省略由模拟器抽样，或提交 `min(N, 合法人数)` 个互不重复的合法目标。无目标池的卡牌仍可空放。UI 不推进随机流，失败的出牌也不消耗目标随机流。即时结算按提交时的目标解析，不存在执行阶段的目标失效重选。
- **扩展准入**：同步引用图涵盖 Effect/Action 链、Buff 首次创建/叠层/移除及同步 GE 钩子。Refresh/Add 与聚合 GE 的有限反馈获准入；移除再创建的反馈、Replace 和可重复 Instant/非聚合 GE 的同步环被拒绝。回合/波次反馈与耗尽实例的纯移除反馈不是同步环。依赖持有者状态的跨互斥组替换、脚本与动态路径由一次技能/球触发共用的深度 32 / 步数 4096 预算兜底；每次命中也消费预算，拒绝次数可诊断。未实现的 ModifyStat 与 Buff 的不支持取值类型在准入层明确拒绝。
- **攻击次数**：直伤与 GAS 统一上限 999；内容的固定 `AttackCount` 与 `AttackCountMinusDiscard` 基准须为 0–999 整数。运行时动态/覆盖数值先在安全范围内夹紧，再转换或叠加，显式固定 0 次保持不攻击。默认 1 次；`AttackCountByChain` 取连携人数且至少 1 次；`AttackCountMinusDiscard` 取基准减实际弃牌数且至少 1 次。物理卡牌再叠加来源的非负整数 `PhysicalCardAttackCount`，总数仍不超过 999。
- **条件身份**：条件上下文保留阵营与索引，敌方与玩家同索引不共享身份。`TookMagicDamageLastTurn` 无参数，只读上一回合玩家槽位的敌方魔法命中账，护盾完全吸收也记账；效果读取来源，目标筛选读取候选，Buff 休眠读取持有者。`OrbTriggered` 按当前钩子的球类型/元素批次判断，两项都指定须同时命中。非玩家来源的出牌条件不能读取全队出牌总数。
- **钩子次数**：条件与执行预算通过后才登记 oncePerTurn/oncePerWave；载荷开始前登记以阻断重入。条件失败不消耗次数，已用尽次数的钩子不随机选目标；多个账期门闩一起登记，避免只消耗其中一个。
- **数据边界**：命令和表现记录保留只读集合快照；手牌与牌堆写入、阶段切换限制为战斗内部操作。数值参数按 invariant culture 解析，拒绝非有限值、整数溢出与小数截断；JSON 数字和原生数字统一要求数学上的整数。参数只合并一次，优先级为定义默认值 < 引用参数 < 技能覆盖；不修改输入。队伍生命裁剪使用聚合后的有效 MaxHealth。

入口：`CombatCommandValidator`、`CombatTargeting`/`CombatTargetResolver`、`SkillPayloadExecutor`、`CombatTurnCoordinator`、`CombatEffectLifecycle`、`DamagePipeline`。修复证据与正式回归见 [系统审查](../../reviews/2026-10-06-combat-audit.md) 与 [差异审查及修复](../../reviews/2026-10-06-git-diff-review.md)。
