# 联机存档影响评估（Run 存档闭环的前置开放项）

> 状态：**评估文档**，非实现规格。本次「Run 存档闭环」（`2026-08-04-run-save-continue-design.md`）按**单机语义**实现；联机影响面记录于此，供联机里程碑另开规格时引用。
>
> 关联总规格：`2026-05-11-kemo-card-design.md` §5.3.1（Run 存档最小字段含「联机槽数据」）、§6（真联机协议与掉线策略为开放项，另开规格）。

---

## 1. 结论摘要

| 影响维度 | 当前单机实现 | 联机需求 | 是否阻塞本次 |
|----------|--------------|----------|--------------|
| 存档字段 | `RunDto` 已含 `SlotOwnership` / `PlayerControllers` / `PlayerStates` | 序列化层已预留 | 否 |
| 写入权威 | 本端 `RunSaveService` 覆盖写 | 需定义「谁写档」（房主 / 权威端） | 否 |
| 自动保存 | 阶段切换点逐处保存 | 各端阶段切换收敛后一致落盘 | 否 |
| 掉线恢复 | 本地单槽 `LoadOrDefault` | 需重连恢复协议，非本地读档 | 否 |
| 快速读取 | 本地覆盖当前会话 | 联机不可本地覆盖（权威冲突） | 否 |

**本次实现不触碰联机语义，也不为联机制造错误的持久化假设。**

---

## 2. 影响面逐项分析

### 2.1 存档写入权威

- 单机：每个客户端读写本地 `user://saves/run`。
- 联机：多人同局时「谁写档、写哪份、何时同步」未定义。候选：
  - **房主权威**：房主保存权威快照，定期或阶段切换时下发。
  - **各端本地 + 加入时同步**：与全局存档模式一致，但需解决分叉。
- 现状 `RunController.Save()` / `RunRuntime.SaveCurrent()` 是纯本地调用，接口**天然可被 RPC 包装**（RunController API 已为此预留，见 run-mod-design §7）。

### 2.2 自动保存的收敛

- 单机：`NextRing` / `EndBattle` / `CreateRun` 逐处触发，静默。
- 联机：阶段切换是**全局事件**（需各端同步确认后进入下一阶段），自动保存应挂在「阶段切换已收敛」之后，而非本端本地切换点，否则各端存档分叉。

### 2.3 掉线 / 重连恢复

- 单机：`TryLoadLatest` 从本地档恢复。
- 联机：掉线玩家需从**权威端**拉取当前 Run 快照恢复，而非读本地旧档。掉线接管逻辑已由 `RunController.OnPlayerDisconnected` 预留（见 run-mod-design §7），但「恢复会话」不在其范围。

### 2.4 快速读取 / 继续游戏

- 单机：覆盖当前会话是合理操作。
- 联机：本地读档会覆盖权威状态 → 禁止或改为「从权威端恢复」语义。

---

## 3. 建议（联机里程碑落地时）

1. 另开规格 **`multiplayer-run-session-save-design`**，覆盖：写入权威、阶段收敛后保存、掉线重连恢复、快速读取的联机语义。
2. 持久化层（`RunSaveService` 原子写 / bak / 损坏降级）可复用；字段已含联机数据，**无需改 DTO**。
3. `RunRuntime` 的静态单例门面在联机下需改造为「会话作用域」对象（每房间一个），当前 `static` 为单人简化。
